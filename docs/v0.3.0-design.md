## 4. 多格式输出管线（需求 3）

### 4.1 单文件执行序（0.3.0）

```
probe(一次) → budget.acquire(2×frame)
  → decode(float32) → orient(如启用) → color(全局目标，一次)
  → 按 targets 顺序逐个：
      [首个破坏 alpha 的 target 之前在工作缓冲原地 flatten（§4.3）]
      encode(target, progress) → metawrite(target 写路径) → 记录 result[target]
  → mtime(仅一次，按 effective DateTimeOriginal)
  → release → 事件(源文件终态 = 聚合：全成功=Done / 任一失败=DoneWithErrors / 全失败=Failed)
```

- **解码一次、编码 N 次**是本需求的性能核心；color 变换全局共享（ColorTarget 全局唯一，D5）。
- 逐 target 串行（同文件内），文件间并行——峰值内存维持 **2× frame**（decode 缓冲 + 工作缓冲），像素预算公式不变。
- BMP target 仍丢元数据 + warning；灰度规则不变（§v1.2 §4）。

### 4.2 输出路径模板（D6 v1.1 修订）

单行模板定义输出相对路径结构，符号可定义可解析：

| 符号 | 展开值 | 示例 |
|---|---|---|
| `$format` | 格式目录名 | `jpeg` / `webp` |
| `$dir` | 源相对目录（不含文件名；空则段坍缩） | `2024/05` |
| `$file` | 文件名.新扩展名 | `IMG_2731.webp` |
| `$name` | 文件名主名 | `IMG_2731` |
| `$ext` | 新扩展名（不含点） | `webp` |

**语法**：段间 `/`；符号可与字面段混排（`photos-$format/$dir/$file`）；未知 `$` 符号=校验错误（`ready_to_start` 阻断）；禁止 `..` 与绝对路径；`$dir` 为空段时坍缩斜杠。解析器 `fsops::render_output_path(template, ctx) -> path`（ctx={format_dir, rel_dir, stem, ext}），纯函数可单测。

**联动**：`split_by_format` 开关 = 模板含 `$format/` 段；UI 开/关自动插入/移除模板首段 `$format/`，手动编辑的其余部分保留。典型模板：开=`$format/$dir/$file`；关=`$dir/$file`；旧 MirrorFirst=`$dir/$format/$file`。

同批次不同源映射同一最终路径（`a/x.jpg`+`b/x.jpg`）仍走冲突策略；**逐输出独立**应用 `resolve_conflict()`，`reserved` 快照按 (out_path) 粒度登记。UI 实时显示单行示例路径（超长省略号，不折行）。

### 4.3 flatten 编排（alpha）

约束：JPEG/BMP 不支持 alpha；WebP/JXL/PNG/TIFF/HEIF/AVIF 支持。**不得复制第三帧**（内存 2× 上限）：

```
targets 排序：supports_alpha=true 的在前，false 的在后（稳定排序保 UI 顺序感由 UI 层重排展示）
最后一个 alpha-preserving target 编码完成后：
    若仍有 alpha-dropping target 且图含 alpha → 工作缓冲原地 flatten（底色规则不变）+ warning
```
全 target 不支持 alpha 且含 alpha → 在首个 encode 前原地 flatten。纯灰度+底色交互沿用 v0.2 语义。

### 4.4 冲突与并发安全

scheduler 的 `inflight` 同目标串行化改为按 **(target.out_path)** 键（一源多输出时不同输出可并行写不同路径）；同一源的多个 target 由同一 worker 串行执行，天然无内部竞态。

## 5. 元数据卡生效值显示（需求 2）

### 5.1 语义

`preview_effective(probe, rules, exception)` 与 `build_plan()` **共用同一套合成逻辑**（抽纯函数，杜绝显示/写入两张皮）：

- 时间：对 `DateTimeOriginal / DateTimeDigitized / DateTime(ModifyDate)` 各出 `EffectiveField<DateTimeVal>`；Δ/时区语义两条路径都走现有 `shift_exif_datetime` / `reinterpret_timezone`。
- GPS：`EffectiveField<GpsData>`；规则未配置 → effective=original；隐私剥除开 → effective=nullopt（显示"将被移除"）。
- `changed` = (effective ≠ original)。

### 5.2 UI 行为（mockup 对齐）

- 一切显示**跟随文件列表选中项**（与地图一致，D4/D8）；无选中 → 显示首个文件 + 「(1/24)」提示。
- 时间卡固定展示 `原（删除线）→ 生效（强调色）`，右端标注来源字段；被改变值加 `.mod` 样式（强调边框+色）。
- GPS 卡输入框显示生效坐标（无 GPS → 空值提示"无 GPS，规则将写入"）；地图 center_on 生效坐标（无=地图保持选点位置）。
- 多选（≥2）：时间卡替换为逐行小表（文件名 | 原 → 生效），上限 8 行 + "…还有 N 个"。
- 关键信息卡字段集（只读）：拍摄时间 · 相机 · 镜头 · 曝光(ISO/快门/光圈/焦距) · 尺寸/位深/通道 · 色彩空间(ICC 有无) · 文件大小/格式 · GPS 有无。
- 异步性：probe 摘要已在文件添加时收集（thumbs 通道）；点选 → 同步纯函数计算（微秒级）→ 即时刷新。

## 6. 预览与分类（需求 1）

### 6.1 预览面板

- 复用 `thumbs` 通道扩展：`decode_preview(path, 2048)` —— 优先内嵌预览（Exiv2/OIIO，≥64px 且长边 ≥2048 可降采样），否则 OIIO 读整图后 LANCZOS3 降采样；独立低并发（≤2）后台线程池，不与转码抢核；LRU 内存缓存（16 张 2048px 上限）。
- 交互（D3）：点选/翻图（←/→）即时替换；缩放「适应 | 1:1」；徽标恒显「输入 · 未修改像素」；底部热键提示 `1 精选 2 待定 3 废片 0 清除`（热键表随分类注册表动态生成）。
- 精度：预览**不做色彩管理之外的任何处理**；色彩管理渲染复用 ColorManager（缩略图口径 v1：sRGB 假定，与既有决策一致）。

### 6.2 分类子系统

- `ClassRegistry`：增删改名/颜色/热键（0-9）；"全部"为保留虚拟分类。默认模板：精选/待定/废片。
- 归属：一文件一分类（可无）；打标即写 registry；持久化 `data_dir()/classes.json`（键=规范化绝对路径；文件不在列表时惰性清理）。
- 自动分组视图：`GroupKey` role 提供 `月份(YYYY-MM) | 相机型号 | 源格式` 三选一 + 「无分组」；QTreeView 节头=组名+计数。
- 圈选语义（D2）：复选框 `checked` = 参与运行 = 批量规则作用范围；分类行右键菜单「全选该类/反选该类/清空勾选」；搜索过滤与勾选正交（勾选状态不因过滤丢失）。

## 7. 进度系统（需求 4）

### 7.1 三级进度模型

```
运行级：总进度 = Σ 输出完成度 / (文件数 × 格式数)（复选文件口径）
源文件级：聚合行 = mean(各输出行进度)；状态 = 阶段态/终态
输出级：阶段权重 + 阶段内 frac（真实或合成）
```

### 7.2 阶段权重表（输出级行进度的确定性来源）

| 阶段 | 权重 | frac 来源 |
|---|---|---|
| probe + acquire | 3% | 即时 1 |
| decode | 27% | OIIO 读行回调（无回调格式即时 1 并日志注明） |
| orient + color | 10% | 即时 1（大图按行计 50/50） |
| encode | 50% | 真实行级 或 合成（§7.3） |
| metawrite + mtime + 落盘 | 10% | 即时 1 |

多输出时源文件级 = 3%+27%+10%（共享段一次）+ mean(各输出 50%+10%)。

### 7.3 合成进度（ProgressSynth）

WebP/HEIF/AVIF 无编码回调 → 估算时长 `t_est = k[format] × pixels / 1e6`（k 校准表随日志实测回归校正），在 `[t0, t0+0.95·t_est]` 上按 `f(x)=1-(1-x)^2` 缓出到 0.95，完成事件跳 1.0；`synthetic=true` → UI 斜纹条纹 + tooltip「合成进度（编码器无回调）」。中途超时过 `t_est` 则停在 0.95 平推（不倒退）。

### 7.4 进度节流与日志

`ProgressMux` 将编码器行回调（每 N 行或每 20ms）汇流为 `FileEvent{state=Progress}`，GUI 节流 60ms 刷新；运行日志每文件落 `progress_max_row/progress_reported` 快照（debug 级）。**进度事件不得淹没日志**（不逐行落盘）。

## 8. 调度器：交错 + 自适应线程预算（需求 5，E3 契约）

### 8.1 交错启动（D10）

全局启动限速器：

```
next_start = max(now, last_start + stagger_ms)   // worker 取件后 spin/sleep 到 next_start
```
`stagger_ms=0` 关闭；设置项 0–2000ms；取消路径立即唤醒所有等待者；日志 `[sched] file 启动（交错偏移 +Δms）`。

### 8.2 自适应线程分配（D11）

纯函数（单测穷举）：

```cpp
struct Alloc { int files; int encode_threads; };
Alloc alloc_threads(int T, int remaining, int inflight) {
    int W = std::min(T, remaining + inflight);          // 目标并行度
    int E = 1;
    if (W * 2 <= T) E = std::clamp(T / std::max(W,1), 2, 16);  // 队列浅 → 放大编码线程
    return { W, E };
}
```

- 语义：剩余文件多（`W*2 > T`）→ 全并行、编码器单线程（=v0.2 行为）；剩余文件少 → 收缩并行、放大 `encode_threads`（上限 16，x265/SVT/libaom/JXL 生效；jpegli/WebP/OIIO 无内部线程，如实记录）。
- worker 取件 → 计算 Alloc → 更新并发闸（信号量限 W）→ `EncodeRequest.encode_threads=E`。
- **E3 契约（替换 E2）**：任一时刻 `Σ 活跃编码线程 + 活跃 worker 主线程 ≤ T + ε`（ε=GUI/IO 线程不计）；编码器不得超配 `encode_threads`；新编码器注册必须声明线程能力表。
- 与像素预算独立正交：内存背压照旧 `2×frame` acquire。

### 8.3 取消语义

不变（阶段边界检查、编码内不中断）；新增：交错等待中的文件被取消 → 立即出 Cancelled 终态事件不进管线。

## 11. 性能与 SIMD（需求 9）

### 11.1 ISA 与工具链 flags（D12/D19）

| 平台 | 项目代码 | vcpkg 依赖（triplet 注入） |
|---|---|---|
| Windows MSVC | `/arch:AVX2 /GL`，链接 `/LTCG` | `VCPKG_C_FLAGS=/arch:AVX2 /GL`、`VCPKG_CXX_FLAGS=/arch:AVX2 /GL`、`VCPKG_LINKER_FLAGS=/LTCG`（成对设置） |
| Linux GCC | `-march=x86-64-v3 -mtune=raptorlake`，`-flto=auto` | 同 flags 进 `VCPKG_C/CXX_FLAGS` |
| Linux Clang | `-march=x86-64-v3 -mtune=raptorlake`，`-flto=thin`（lld） | 同上 |

- Triplet：`x64-windows-avx2.cmake` / `x64-linux-avx2.cmake` 自定义 triplet 继承默认；`cmake/avx2.cmake` 统一定义项目 flags（MSVC `/arch:AVX2`；编译器不识别 raptorlake 时回退 `-mtune=haswell` 的探测式设置）。
- 库级 SIMD：x265/SVT/libaom NASM 运行时派发（flags 不影响其汇编，自动取 AVX2 内核）；jpegli/libjxl Highway 运行时派发（`HWY_DISABLED_TARGETS` 可裁剪 pre-AVX2 target 以减体积，可选）；libwebp `simd` feature 保持；**OIIO 显式 `-DUSE_SIMD=avx2`**（防默认 sse4.2 口径变化）。
- LTO 只作用于自研 targets（`pp_core`/`photopipeline`）；PGO 列为可选延伸（不在必达）。

### 11.2 自研热路径 SIMD 化（`src/core/simd/`）

| 热路径 | 现状 | 0.3.0 | 实现 |
|---|---|---|---|
| `flatten_alpha` | 标量循环 | AVX2 8px/迭代 FMA 混合 | `flatten_avx2` + `flatten_ref`（测试对比逐位） |
| float→int 舍入（encode 前） | 标量 | AVX2 `_mm256_cvtps_epi32` + saturate | `quantize_avx2/ref` |
| orientation 转置/镜像 | `ImageBufAlgo`/标量 | AVX2 分块转置 | `transpose8_avx2/ref` |
| 缩略图 LANCZOS3 降采样 | Qt/OIIO | AVX2 水平+垂直两次卷积 | `downscale_avx2/ref` |
| 通道交织/解交织（编码器入参） | 标量 | AVX2 gather/permute | `interleave_avx2/ref` |

纪律：每对 `*_avx2 / *_ref` 同签名；单测对随机缓冲断言（flatten/interleave 逐位相等、quantize 舍入一致、transpose 逐位、downscale 容差 ≤1e-5）；运行期 `cpu_has_avx2()`（CPUID）选择实现（**仅此一层运行时分派**——基线本就 AVX2，ref 路径服务测试与调试）。

### 11.3 性能验收

- 基准场景（`--dev bench` 新增，dev-only）：48MP TIFF→JXL、24MP JPEG→WebP×16 文件批、单张 HEIF。
- 验收：多格式（jpeg+webp）对比两次单格式运行，总耗时 ≤ 1.35×（证明解码共享生效）；批吞吐不低于 v0.2（禁回退）；flatten SIMD ≥ 2× 标量（微基准）。
