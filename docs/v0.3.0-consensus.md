# PhotoPipeline 0.3.0 需求共识文档（M4 头脑风暴结论）

> 状态：**需求共识已达成（5 轮 × 21 项交互式决策）；设计定稿见 `docs/v0.3.0-design.md`，任务书见 `docs/m4-tasks.md`。**
> 形成方式：5 轮批量交互式提问（分类与预览 → 输出与元数据 → 运行与并行 → GUI 骨架与 CI → 依赖与工程纪律）。
> 本文档只记录"是什么"与"为什么"，不含接口与实现；GUI 视觉定稿见 `docs/mockups/`（4 张高保真原型，已迭代并经用户待确认）。
> 版本对应：**0.3.0 = 里程碑 M4**（M0–M3 已完成 0.1.0/0.2.0 发行）。

## 1. 0.3.0 主题

一句话：**从"能用的转码器"到"高吞吐多格式批处理工作台"**——输入预览与分类、生效值元数据、多格式输出、逐文件进度、自适应并行、现代 GUI、工业级 CI、依赖全升、AVX2 性能目标。

0.3.0 九项需求（用户提出，逐项展开见 §3）：

| # | 需求 | 一句话结论 |
|---|---|---|
| 1 | 预览 + 图片分类 + 文件列表勾选 | 常驻输入预览面板；手动命名分类 + EXIF 自动分组视图；列表加复选框 |
| 2 | 元数据卡片显示生效值 | 时间/GPS/地图跟随选中文件显示"原 → 生效"；新增关键信息卡 |
| 3 | 输出格式多选 | 8 格式复选多选、逐格式页签参数；多选默认按格式分文件夹（两种结构可配置、可取消） |
| 4 | 逐文件进度 | 阶段权重 + 编码行级子进度；无回调编码器走合成进度（斜纹条标识） |
| 5 | 并行不同时启动 + 线程平衡 | 交错启动（固定间隔可配置）；自适应线程预算（文件级并行 ↔ 编码器内部多线程动态分配） |
| 6 | GUI 重构 | 常驻预览 + 三步内容区骨架；现代 Fluent 视觉体系（明暗双主题） |
| 7 | CI 重构 | Windows-first 双平台快慢道工业流水线；job 与整轮双 ≤20min 硬约束 |
| 8 | 关键库升级 | 能升尽升一把全升（Qt 6.11.2 / libjxl 0.12 / exiv2 0.28.9 …）；不能升的明确停留 |
| 9 | 编码库编译性能 | **AVX2 目标（以 i7-14700K 为优化目标）**；库级 SIMD 全开 + 自研热路径 SIMD；不要求 pre-AVX2 兼容 |

## 2. 五轮交互式决策全表（21 项）

### 第 1 轮 · 分类与预览（需求 1/2）

| # | 议题 | 裁定 |
|---|---|---|
| D1 | 图片分类语义 | **手动分类 + 自动分组**：用户创建命名分类（颜色点+热键 1–9），另提供按 EXIF 的自动分组视图 |
| D2 | 分类的作用 | **组织 + 批量选择**：过滤列表、整类勾选；配合文件列表复选框圈定参与运行/批量规则的范围；不改变输出内容、不绑定规则 |
| D3 | 输入预览形态 | **常驻预览面板**：列表点选 → 中栏即时显示输入大图（色彩管理渲染），←/→ 翻图 + 数字键打标；**只预览输入，不预览输出** |
| D4 | GPS/MAP 跟随语义 | **跟随选中文件，只显生效值**：地图显示该文件最终写入坐标（无修改=原坐标）；不做新旧双钉对比 |

### 第 2 轮 · 输出与元数据（需求 3/2）

| # | 议题 | 裁定 |
|---|---|---|
| D5 | 多格式参数区组织 | **格式页签**：复选框行下方 QTabWidget，每个已选格式一页签，页签内含位深 + 全部编码参数 |
| D6 | 分文件夹结构 | **路径模板**（v1.1 修订，替代原"两种结构二选一"）：`$format`/`$dir`/`$file`/`$name`/`$ext` 可定义可解析符号自由组合；「按文件格式分文件夹」保留为**单行开关**（联动模板是否含 `$format` 段）；不勾选 = `$dir/$file` 现状直出 |
| D7 | 仅元数据 × 多选 | **互斥：禁用多选**（保持 v0.2 语义：源格式零重编码原样输出） |
| D8 | 时间显示粒度 | **跟随选中文件**："原拍摄时间 → 生效时间"常显（未修改时两值相同）；多选文件时逐行小表 |

### 第 3 轮 · 运行与并行（需求 4/5/9）

| # | 议题 | 裁定 |
|---|---|---|
| D9 | 逐文件进度粒度 | **阶段权重 + 行级子进度**：JPEG/JXL/PNG/TIFF 真实行级进度；WebP/HEIF/AVIF 合成进度（斜纹条标识）；多格式时逐输出行 + 源文件聚合 |
| D10 | 交错启动策略 | **固定间隔可配置**（默认 ~150ms，0–2000ms 可调，0=全部立即） |
| D11 | 线程平衡策略 | **自适应预算**：总并行预算 = 逻辑核数 N；队列深 → 多文件并行+编码器串行；剩少量大文件 → 收缩文件并发、给 x265/SVT/libaom/JXL 开内部多线程；总活跃线程 ≤ N |
| D12 | ISA 目标 | 初选 AVX-512 直升 → **终裁改为 AVX2 目标（用户 CPU i7-14700K 为优化目标，放弃 AVX-512）**。理由：消费级 Raptor Lake 无 AVX-512；AVX2 (x86-64-v3) 兼顾 CI 免费 runner 与目标硬件，消除 SIGILL 风险 |

## 3. 九项需求展开

### 3.1 预览、分类与文件列表勾选（需求 1）

- **输入预览面板**（中栏常驻）：点选列表行 → 显示输入大图（解码+色彩管理渲染，缩放适应/1:1）；←/→ 翻图；文件名/尺寸/位深/色彩空间随图显示；徽标注明「输入 · 未修改像素」。
- **手动分类**：命名分类（默认四档模板：精选/待定/废片/可自建），带颜色点、计数、热键 1–9 打标、0 清除；预览底部显示打标热键提示；分类持久化到数据目录（跨会话保留）。
- **自动分组视图**：文件列表分组切换（无 / 按月份 / 按相机型号 / 按源格式），分组头带计数；纯展示性分组，不产生数据。
- **文件列表复选框**：勾选 = 参与运行（= 批量规则作用范围）；Ctrl+A / 分类行整类勾选配合使用；全选/全不选/反选入口。
- 边界：分类只做组织与圈选（D2），**不**绑规则、**不**绑输出设置（负面清单更新见 §5）。

### 3.2 元数据卡片生效值显示（需求 2）

- **关键信息卡（新增，常显）**：跟随选中文件展示——拍摄时间、相机、镜头、曝光（ISO/快门/光圈/焦距）、尺寸/位深/通道、色彩空间(ICC 有无)、文件大小/格式、GPS 有无。只读展示，不管是否修改。
- **时间偏移卡**：偏移控件不变（Δ/时区语义），**新增"生效时间"对照行**：`原时间 → 生效时间`（删除线原值 + 高亮生效值），来源字段标注；跟随选中文件；多选时逐行小表；未修改时两值相同也要显示。
- **GPS 卡**：输入框显示**生效坐标**（跟随选中文件；规则未覆盖=原坐标）；地图跟随选中文件居中显示生效值钉（D4，只显生效值不画新旧对比）；"从选中文件读取 GPS/清除 GPS/地图选点"保留。
- 改动值视觉规范：所有被规则改变的值用强调色+微光标记（见 mockup 的 `+8` 高亮样式）。

### 3.3 输出卡片多格式（需求 3）

- **输出格式复选磁贴**（8 格式）：选中即输出，可多选；头部计数「已选 N」；单选=与 v0.2 行为一致（1 输入 1 输出）。
- **格式页签参数区**（D5）：每个已选格式一页签（JPEG | WebP | …），页签内含**该格式位深**（联动格式能力，如 JPEG 锁 8 位）+ 全部编码参数（现有 ParamForm 原样嵌入）；页签右端「＋添加格式…」快捷入口；页签上改动计数徽标。
- **全局区**：输出根目录、同名冲突策略、色彩目标（全局一项）+ **「按文件格式分文件夹」开关**（多选时**默认勾选**，可手动取消；单选时默认不勾）。
- **输出路径模板**（D6 v1.1 修订）：单行输入框接受 `$` 符号模板定义输出结构：
  - 符号集：`$format`=格式目录名（jpeg/webp/…）、`$dir`=源相对目录、`$file`=文件名.扩展名、`$name`=文件名主名、`$ext`=扩展名（不含点）
  - 语法：`/` 分隔；符号与字面目录段可混排（如 `photos-$format/$dir/$file`）；未知 `$` 符号 = 校验错误（阻断开始运行）；禁止 `..`；`$dir` 为空段时坍缩斜杠
  - 典型值：勾选分文件夹=`$format/$dir/$file`；取消=`$dir/$file`；旧"根/镜像/格式"=`$dir/$format/$file`（符号组合天然覆盖原二选一）
  - 「按文件格式分文件夹」单行开关与模板联动（开=模板含 `$format/` 段）；UI 实时显示单行示例路径；逐输出文件独立走冲突策略。
- **仅元数据模式互斥**（D7）：切到仅元数据 → 格式多选区禁用并提示；反之恢复。
- **输出量预告**：底栏「N 个文件 × M 个格式 = N×M 个输出 · 预计体积」。

### 3.4 逐文件进度（需求 4）

- 运行页任务列表 = **源文件分组行 + 逐输出子行**（多格式时一个源文件 N 行输出）。
- 每输出行：**进度条 + 百分比 + 阶段文字**（解码/色彩/编码+行数/写入/完成/失败）。
- 真实进度（行级）：JPEG（jpegli 按写扫描行）、JXL（编码回调）、PNG/TIFF（OIIO 写行）；
  合成进度：WebP/HEIF/AVIF（编码器一次性无回调）→ 按图像尺寸估算时长的平滑推进，**斜纹条纹样式**明确标识合成进度，完成时跳满。
- 完成行显示产物事实：字节数 · 压缩比 · 耗时；失败行直显原因（如「16→8 位降档被禁止」）。
- 总览条：总百分比（= Σ 输出完成度/总输出数）、吞吐、并行 workers、交错间隔、线程预算模式、取消按钮。

### 3.5 并行运行（需求 5）

- **交错启动**（D10）：worker 取到新文件后延迟 stagger_ms（默认 150ms，0=立即）再开跑；设置可调 0–2000ms；日志记录每文件启动偏移。
- **自适应线程预算**（D11，解冻 E2 → 新契约 E3）：
  - 总预算 T = 逻辑核数（可配置上限）；调度器维护"文件级并行度 W × 编码器内部线程 E"的分配：`W×E ≤ T`。
  - 队列深（剩余文件 > T/2）：W=T、E=1（现状行为）；队列浅/大文件：收缩 W、放大 E（x265/SVT/libaom/JXL 接受线程参数；jpegli/WebP/PNG/TIFF 无内部线程可用——库限制如实告知）。
  - 运行页实时显示当前分配（「3 文件并行 + 1 编码器多线程」）。
  - 像素预算（内存背压）机制原样保留，与线程预算并行不悖。

### 3.6 GUI 重构（需求 6）

- **骨架**（D13）：左=文件列表(勾选/分组/搜索/分类面板)，中=常驻输入预览，右=三步内容区；顶栏步骤导航+预设/设置；底栏摘要+开始。
- **现代视觉**：8px 卡片圆角 / 4px 控件圆角 / 4px 节奏栅格；Segoe UI Variable 排印；系统强调色；明暗双主题跟随系统；Mica 材质保留（Win11）；改动值高亮、徽标体系、迷你进度条、斜纹合成进度等控件规范。
- **可视化定稿**：`docs/mockups/meta-dark.png`（元数据页·深色）、`output-dark.png`（输出页）、`run-dark.png`（运行页）、`meta-light.png`（浅色主题），HTML 源同目录（可重渲）。**待用户确认后冻结为实现依据**。

### 3.7 CI 重构（需求 7）

- **Windows-first**：开发机=Windows 11（i7-14700K），CI 主平台 windows-2025，Linux 保持同等质量门禁（双平台系统性目标）。
- **快慢道**（D14）：
  - **PR 快速道**（目标 <10min）：clang-format 门禁 → 双平台构建（缓存热）→ 单元测试 → 金样冒烟子集；
  - **主干/每日全量道**（≤20min）：双平台全构建 + 全 ctest + 金样全量 + UI 冒烟 + 打包(AppImage/winzip) + 产物烟测 + 发布预检；
  - **夜间道**：ASan/UBSan/TSan 全语料 + 回归基线 diff + 依赖/许可审计。
- **质量门禁**（D15）：clang-format 硬门禁；clang-tidy 棘轮制；SPDX/许可审计硬门禁；金样断言级全量。
- **双约束**（D16）：每个 job ≤20min 且整轮 wall-clock ≤20min；流水线逐 job 预算表入设计文档，超预算即重构。
- 系统化要求：阶段化 DAG（lint→build→test→golden→package→smoke→publish 前置探测）、缓存策略明文化、每阶段耗时进 Step Summary、发布链路加固（M3 遗留）。

### 3.8 依赖升级（需求 8）

**一把全升**（D18），逐库结论见 `docs/v0.3.0-design.md` §10。要点：

- **升**：Qt 6.8.3→**6.11.2**、libjxl 0.11.2→**0.12.0**（修 box 写入真 bug，与我们 JXL 元数据路径直接相关）、OIIO 3.1.14→**3.1.17**、exiv2 0.28.8→**0.28.9**（顺删已弃用 `enableBMFF()` 调用）、libheif→**1.23.5**、x265→**4.3**、SVT-AV1→**4.2.0**、aom→**3.15.1**、libde265→**1.1.3**（CVE 累积必升）、dav1d/zlib/zstd/lcms/spdlog/libwebp/highway 对齐上游最新、CMake 兼容线升至 4.x。
- **不升/停留**：**OIIO 3.2**（未 GA，等 2026-10 后单独排期）、**exiv2 main/0.29-dev**（不跟）、**jpegli**（上游无 tag/release，保持钉 commit `031a0077`，重钉=整体回归）、**SVT-AV1 3.x→4.x 不可盲跳**（我们已在 4.x，只走 4.1→4.2）。
- vcpkg baseline tag 2026.07.29 已是最新 tag；超前版本走 overlay port（现有 overlay 机制延续）。

### 3.9 编码库编译与性能（需求 9）

- **ISA 目标（D12/D19 终裁）**：**AVX2（x86-64-v3）为编译基线，i7-14700K（Raptor Lake）为调优目标**；不要求 pre-AVX2 兼容；放弃 AVX-512 直升（消费级 Raptor Lake 无 AVX-512，且保 CI 免费 runner 可跑）。
- 库级 SIMD：x265/SVT-aom/libaom NASM 内核 + 运行时 CPU 派发自动生效；jpegli/libjxl（Highway）运行时派发；libwebp `simd` feature；OIIO 显式 `USE_SIMD=avx2`。
- 全局编译 flags 经 vcpkg triplet 注入（`VCPKG_C/CXX_FLAGS=/arch:AVX2`、`-march=x86-64-v3 -mtune=raptorlake`；LTO 可选 `/GL+/LTCG`、`-flto=thin`）。
- **自研热路径 SIMD**：alpha 合成、float→整型舍入、方向旋转变换、缩略图降采样、通道交织/解交织（AVX2 内在函数，标量回退供测试对比）。
- PGO 作为可选延伸目标（只作用于自研代码），不在 0.3.0 必达范围。

## 4. 对 v0.2 需求共识的修订（增量）

1. **负面清单松绑两项**（用户需求驱动）：「大图预览」→ 允许**仅输入预览**（服务分类）；「图库/评级/管理类功能」→ 允许**轻量分类标签**（仅组织+圈选，不是图库管理）。
2. **输出语义升级**：单格式 → **多格式并行输出**（解码一次编码多次）；输出目录结构新增按格式分文件夹（两种结构可配置）。
3. **线程契约 E2 → E3**：v0.2「编码器内部线程全部关闭」解冻为「按自适应预算分配，总活跃线程 ≤ T」。
4. **接口冻结纪律延续但集中解冻一次**（D20）：M0–M3 的 PP-FROZEN 纪律不废，0.3.0 以"解冻裁定表 + 再冻结"方式推进。
5. **性能目标具体化**：AVX2 基线 + 14700K 调优（原共识仅"高质量高性能"原则）。
6. **CI 从"能跑"到"工业流程"**：新增快慢道、质量门禁、双 20min 硬约束、发布前置探测。

## 7. 决策背后的硬事实（0.3.0 新增）

1. **WebP/HEIF/AVIF 无编码进度回调**（libwebp 一次性编码、libheif 不透传 x265/SVT 进度）→ 合成进度是唯一诚实做法，UI 必须明示（斜纹条）。
2. **jpegli/WebP/OIIO 无内部线程开关**（jpegli 天生单线程、WebP 仅 thread_level 0/1、OIIO 写出单线程）→ 自适应线程预算的"放大 E"只对 x265/SVT/libaom/JXL 有效。
3. **Qt 6.8 LTS 公开补丁已停**（6.8.5+ 商业订阅专属）→ "保守停留"实际=停止收补丁；6.11.2 Widgets 增量演进无破坏。
4. **libjxl 0.11 的 box 追加有损坏文件的上游 bug（#4466）**，恰在我们 JXL 元数据写入路径上 → 0.12 升级是修复而非追新。
5. **exiv2 `enableBMFF()` 自 0.28.4 起弃用且无替代 API**（BMFF 由构建期 feature 决定）→ 正确动作是删调用，不是找替代。
6. **x265/SVT-aom/libaom 的 x86 热路径是 NASM + 运行时派发**，全局 `/arch` 只影响 C 兜底 → AVX2 目标主要约束自研代码与基线，库内 SIMD 自动到位。
7. **消费级 i7-14700K（Raptor Lake）无 AVX-512** → AVX-512 直升对目标硬件无收益，AVX2 是正确基线。
8. **GitHub 免费 runner 全支持 AVX2**（x86-64-v3）→ CI 无 SIGILL 风险、无需自托管。
