### 0.2 用户已拍板的关键决策（详见 §15）

1. **基线** = `0.3.6.alpha2` 发行版（含 M9）。
2. **并行范围** = A（评分流式化/独立评分池 + 双 probe + 预算/E3 修正）**+ B1（同文件多格式并行编码）**。
3. **确定性口径**：不削减编码器线程（用户指出编码器本就多线程）；确定性只作为既有回归门禁约束（workers=1 zero diff）保留，**不引入"线程数模式"**。
4. **评分默认**：保持默认开 + 指标流式化/独立评分池（根治 P0 与卡顿）。
5. **JXL**：同时改默认值（`epf/dots/patches/gaborish` 三态跟随库默认）**并确认重播种回归基线**。
6. **HEIF grid/Level**：Level 上移主配置区；grid 默认按 Level 自动；tile 自动推导 + 高级可手动覆盖。
7. **still 档**：新增 6 档（编号 16–21）+ 修正 3 个误导标签；**同时修下拉框"看不全"问题**（弹出层自适应加宽+省略+tooltip）。
8. **tune**：HEIF animation 用仿真、zerolatency/vmaf 置灰；AVIF-libaom 扩 `ssimulacra2/vmaf_saliency_map`（内部 `aom:tune` 通道）。**不 patch libheif**。
9. **自适应策略形态**：行式 DSL 文本，**GUI 不提供编辑器，策略只存在于格式预设文件里**；最多轮数也在预设文件中配置。
10. **格式预设存储**：独立文件 `<数据目录>/presets/formats/<格式>/<名>.json`，每格式独立命名库。
11. **运行页**：删速度列（压缩比入大小列 tooltip）+ 列宽模型（状态 96/大小 56/耗时 44）+ 中间省略 + 全路径 tooltip。
12. **引擎逐输出事件**：接受加性改冻结事件面（逐输出完成/评分即时到达）。
13. **交付**：一个里程碑 M10 / 0.4.0，分 3 波实现；**先交详细设计与开发计划，用户确认后才可开工**。

## 1. 目标与非目标

### 1.1 设计目标

- **G1 性能**：把"输出时长"从"评分单线程 + 预算串行 + 多格式串行"的三重叠加中解放出来；默认配置即高效，用户无需调参。
- **G2 诚实可见**：运行页的状态/进度/评分与实际引擎事件同源、即时、可解释（"评分中"也是状态）；不显示没发生的量。
- **G3 参数面收敛**：把 M8"全参数暴露"从"能列出"推进到"每个键都真实生效/有技术作用域/有默认语义"；不能生效的键诚实删除/只读/置灰。
- **G4 可复用配置**：格式级预设（含自适应策略）让"一套 JXL/HEIF 参数"跨批次复用；与全局预设职责清晰、互不污染。
- **G5 质量可编程**：自适应调参把"评分 ≥90"变成可执行、可复算、可审计的策略；策略是人类可读可写的文本，随预设文件走。
- **G6 工程可验收**：每个需求有机械化探针；默认行为可回归（zero diff），新能力默认关闭。

### 1.2 非目标（本里程碑明确不做）

- 不做图像编辑/缩放/降噪/HDR 等像素处理（负面清单不变）。
- 不做全局阶段流水线（B2：decode 池→encode 池→score 池）——本轮只做 A + B1，B2 留待独立论证。
- 不做"编码器内部瓦片并行"（B3：分块编码会改变产物字节，撞"不降级/回归"红线）。
- 不 patch libheif/x265 依赖；不升级 vcpkg 依赖版本。
- 不做自适应策略的 GUI 编辑器（用户裁决：策略只在预设文件里）；GUI 只显示只读摘要与启用开关。
- 不做"多格式输出完成顺序"的 UI 行序变化（行序恒为配置顺序）。
- 不把评分权重塞进进度权重表（保持 overall_frac 语义稳定；评分用独立状态+心跳表达，见 §4.6）。
- 不做 iPhone 真机验收（沿用 M9 未决项：Apple 接受度需真机，本设计如实标注风险）。

## 2. 现状与根因（设计的事实底座）

> 证据：本机 `build/design-recon/`（gitignored）内的 34 轮 summary/log/trace、54 例 JXL 探针产物、28 例 HEIF 探针产物、真实事件流与 UI 回放脚本。以下数字均可由报告 §11.1 / §7 的命令复跑。机器：16 逻辑核；像素预算容量实测 8 GiB。

### 2.1 需求 1/9：并行与多核（根因按命中概率排序）

| ID | 机制 | 代码链 | 实测 |
|---|---|---|---|

### 2.2 需求 4：输出链路（22.8MP 单文件、info 日志、GUI 默认评分）

| 段 | JXL | HEIF | 说明 |
|---|---|---|---|
| decode | 0.15s (0.8%) | 0.11s (0.7%) | sidecar decode_ms |
| encode | 5.16s (29%) | 2.71s (17%) | sidecar encode_ms |
| **score** | **12.18s (68%)** | **12.45s (80%)** | `quality metric.ms` |
| metawrite+mtime | 0.001s | 0.001s | 元数据内嵌 |
| 其它（probe/plan/收尾） | ~0.33s | ~0.33s | TIFF 双 probe 便宜 |
| **合计 wall** | 17.82s | 15.60s | encode 占比仅 17–29% |

卡顿点按可优化收益排序：
1. **同步单线程评分**（12.2–12.5s/23MP，占 68–80%；`metric.cpp` 单线程 + 回读产物解码）——`pipeline.cpp:1514-1516`、`compat_core.h:20`。
2. **评分色彩归一慢（D-1：原"逐行 lcms"归因经 W1-T1 实测证伪）**：默认 keep 路径下评分需把"参考帧/失真帧"各自从源空间归一到 sRGB 线性，实测**单次整帧 22.8MP AdobeRGB→sRGB lcms≈3.34s，两次≈7s**；按带化（band=64 行）只消固定开销（row/band≈0.97，无提速）。`--color srgb` 隔离实验的 12.18→4.73s 差异来自"免 lcms"而非"按带"。**真正修复 = 快速归一内核（新任务 W1-T2c：3D CLUT/SIMD 近似 + 数值对拍），或复用既有归一结果；不得以"按带"冒充修复。**
3. **预算把并发压到 1–2**（R1-a）。
4. **双重 probe**（HEIC 1.65s/文件=22–44% wall；W1-T1 已实现 A4 复用，实测 2902.9→1447.8ms）。
5. **多格式严格串行**（4 格式 19.58s；webp 单文件编码 11.96s）。
6. **exiv2 metawrite 整文件拷贝+重写**（`metadata.cpp:856-912`）：162MB TIFF 1.40s（encode 1.54s 的 90%）、118MB PNG 0.84s。**D-2：exiv2 承载格式的编码器故意不内嵌 EXIF/XMP，"无手术"≠可跳过写回（跳过会删源元数据、金样红）→ 原 C9 快路径只在"源本身无元数据"子集成立；大幅节省需改编码器内嵌或免拷贝原子写，另立任务（P2）。**
7. **debug 日志洪水**（debug 级下每行 lcms 一条日志；8 文件评分批 59,484 条 / 16MiB 上限被截断；GUI 默认 info 不触发，但 `--dev` 取证会被放大 10–20%）。W1-T1 已实现限流：color 日志 11708→2 行、单文件 debug 11740→35 行。

### 2.3 需求 5/6：运行页（像素账 + 事件回放）

- 列 = `[标记16][名称stretch][进度88][大小60][速度48][耗时48][评分44][状态132]`，列距 6×7=42，行内距 24，卡内距 24，滚动条 6（`page_run.cpp:124-137,1581-1617,1987`）。
- 右栏 587 时：名称列 = 587−532 = **55px**；右栏可拖到 520 → 固定列本身溢出 12px。
- 实测：`--ui-smoke` run-score 探针 name_w=84 → 内容宽 610 > 视口 581（溢出 29px）；真实运行截图 name N=100 → 内容宽 626 > 581（溢出 45px，状态列整列不可见/胶囊被切 5px）。
- 长文件名：68 字符名批次几何与普通批次相同（省略吸收，未额外放大溢出），但名称列仍 ~100px、右侧照样裁。

- 根因（file:line）：组行 = `file_status()` 默认分支只回显 `shared_stage`，而共享段事件止于 Color（`page_run.cpp:760-803,899-946`）；格式行 = `out_stage_text()` 只要 height>0 就显示"编码 N/M 行"，百分比是死兜底（`:702-725`）；完成/评分只在 `apply_terminal`（`FileEvent.result` 非空，仅文件终态）落 UI（`:948-1001`、`scheduler.cpp:244-258`）。

### 2.4 需求 2/3/8/12：HEIF/AVIF 参数面（已有 vs 缺口）

## 4. 需求 1 / 4 / 9：性能、输出链路与并行

> 设计原则：**不推翻调度架构**（文件级并行实现是好的：无评分 8 文件 2.78×、峰值并发 7）；修的是"默认值自毁 + 评分单线程同步 + 单文件多格式串行 + 长尾无事件"。

### 4.1 目标（可机械断言，见 §12）

见 §0.3 SLO 表。核心三条：
1. GUI 默认 8×24MP 评分批 wall ≤20s、CPU ≥8 核（同机同素材）。
2. 单文件 23MP 单输出：`metric_ms ≤ 0.6×encode_ms` 且 `wall ≤ 1.5×encode_ms+2000ms`。
3. >45MP 图片 + 评分必须成功产出（评分可异步/降级为 `Unavailable`，但文件不得失败）。

### 4.2 评分链路重构（A1+A2；需求 4/9 的第一主因）

#### 4.2.1 现状偏差（必须先认清）

M8 设计 C10 原文要求"指标模块必须**流式/分块**处理，峰值 ≤ 现有 2×frame 像素预算（不重播种基线）"（`docs/m8-encoder-params-and-ssimulacra2-design.md:102,249-254`）。HEAD 实现：
- `metric.cpp:109-146` 物化两整帧 + 官方金字塔（自述 130–160B/px）；
- `pipeline.cpp:801-806` 因此按 `+160B/px` 给每个文件加预算 → 24MP=4.42GB → 8GiB 容量并发 1；
- `pipeline.cpp:1191-1235` 注释说"64 行带缓存只做一次 lcms"，实现逐行调用 `rgb_row_to_srgb_linear`（每行构造 ImageBuf + ICC SHA1 缓存键 + ColorManager）→ 每 23MP 白扔 ~7.45s；
- debug 级每行一条 `colour transform applied` 日志（8 文件批 59,484 条，16MiB 上限截断）。

#### 4.2.2 设计（三级递进，同批落地）

**(1) 指标流式化（A1）**
- 复用 M8-C10 的分块方案：按行带（带高 = 64 行 + halo）计算 6-scale 金字塔的 SSIM/边缘统计并累加 108 范数；不物化整幅 XYB 金字塔；参考侧与失真侧都按行带取数。
- 峰值额外内存目标：≤ 1 帧 + 少量 scratch（≤ 8B/px 量级）；`need = 2×frame` 恢复为"文件预算"口径，评分不再逐文件加 160B/px。
- 数值一致性：与 HEAD 现实现做 oracle 对拍（同一组 5–8 对图，覆盖 8/16 位、灰度、宽色域、HDR 源、alpha 拍平），要求 |Δ|≤0.01；同时保留 PyPI `ssimulacra2` 独立 oracle 抽查（M8-C13 先例）。
- 退出条件：24MP 单输出 metric ≤0.6×encode（23MP 目标 ≤3.1s；流式+AVX2 预计 1.5–2.5s）。

**(2) 独立评分池 + 异步（A2）**
- 新增进程级 `ScorePool`（`core/score_queue.{h,cpp}`，新文件，不冻结）：K 个 worker（K = `min(4, max(1, hardware/4))`，可用设置预留但本版不暴露 UI）；任务 = {源参考行源, 产物路径, 输出目标参数, 上下文}；结果 = `MetricResult{state, score, ms, note}`。
- 管线顺序改为：`encode → metawrite（写盘完成）→ 发 OutputDone（不含 metric）→ 提交评分任务`；评分完成后由评分池发 `OutputDone`（更新版，含 metric）→ UI 即时刷新评分列。
- 评分池内存独立配额：`score_budget = min(capacity×0.5, K×单任务需求)`；单任务需求随流式指标下降（约 2 帧 + scratch）；当 `单任务需求 > score_budget`（超大图/低内存机）→ 该输出评分标记 `Unavailable`（note="内存不足，已跳过评分"）而**文件仍成功**（P0 修复）。
- `--dev` 证据面：dev_cli 在 scheduler wait 后**等待评分池收敛（带超时/取消）**，再写 sidecar/退出码，保证证据完整且可复现。
- 取消：取消时评分池任务按 token 放弃；已排队未开始的直接丢弃；不产生不完整分数。
- 与设置开关的关系：`quality_score=true` 时进入上述异步评分；`false` 时不提交评分任务（`metric_state=Off`）。

**(3) 按带 lcms + 日志限流（C4）**
- 把 `MetricLinearRows` 的"逐行调 `rgb_row_to_srgb_linear`"改为"按整带（64 行）一次调用"：`rgb_rows_to_srgb_linear(const ImageBuf&, y0, h, ...)`，每带只构造一次变换（缓存命中时零 lcms 开销）；每带内部行连续，减少 ImageBuf ROIs 与哈希构造。
- 删除/降频 `colour transform applied`：改为每次 `transform()` 调用一条 debug（或每文件一条 info），并加"同 (src,dst) 首见+计数"限流；`--log-level debug` 下全文件日志量 ≤ 每文件 100 行量级。
- 预期：23MP 单输出 metric 12.18→4.73s（隔离实验已证明的收益）+ 流式进一步降到 1.5–2.5s；日志洪水消失。

**(4) 指标内并行（可选，P2）**
- 流式指标天然可按带并行（band 间独立）；`third_party/ssimulacra2` 兼容层的 `RunOnPool` 目前串行。P2 可接 `JxlThreadParallelRunner` 或自写固定线程池，单文件单输出再 2–4×；**默认关闭**（避免与评分池叠加过订阅），作为 >45MP 兜底。

### 4.3 预算 / 调度默认值（A3+A5+C6+C7）

| 项 | 现状 | 设计 | 回归影响 |
|---|---|---|---|
| 文件预算 need | `2×frame + 160B/px×score` | `2×frame`（流式评分不再占文件预算）；评分用独立 `score_budget` | 无产物影响；`pixel budget` 日志键不变（need 数值变化需在实现批归因） |
| 预算容量 | `min(可用RAM×50%, 8GiB)` | 不变（本版不新增设置；>45MP 由"评分可 Unavailable"兜底，不再失败） | 无 |
| stagger 默认 | 150ms | **0**（关） | 无产物影响；调度顺序变化（回归 workers=1 不触发） |
| `quality_score` 默认 | true | 保持 true（用户裁决） | 无产物影响；评分异步后 wall 结构变化，基线日志含 metric 行（评分批不在回归语料） |
| E3 | `W=min(T, remaining+inflight)`；E 由 W 反推 | 引入 `W_eff = min(W, floor(capacity/need_file), hw)`；`E = clamp(T/max(W_eff,1), 1, 16)`（E=1 分支保持：W_eff*2>T 时 E=1；W_eff*2≤T 时放大） | `[sched] thread alloc` / `e3 report` 数值在"浅队列/单文件"场景可能变化 → 实现批逐项归因，必要时登记重播种 |

### 4.4 同文件多格式并行编码（B1）

#### 4.4.1 模型

```
run_one_file（worker 线程）
  ① probe（复用 C8 缓存）
  ② budget.acquire(2×frame)                      ← 文件预算不变
  ③ decode → orient → flatten → color             ← 共享段（一次）
  ④ 逐 target 规划（路径/冲突/排序在解码前已定）
  ⑤ 并行 encode+metawrite：N 个 target 任务（N' = min(max_parallel_targets, targets)）
       每个任务独立：encoder 实例（现状即每 target 构造）→ encode → metawrite → 发 OutputDone
       预算：每个并行任务额外 acquire "编码器缓冲" token（按格式/位深估算，见 4.4.3）
       score：任务结束后提交 ScorePool（异步），不阻塞任务
  ⑥ 全部任务 join（或失败/取消收敛）→ 发评分后事件由池负责
  ⑦ mtime / reserved 登记 / 聚合终态（保持现状顺序）
```

- **共享帧只读**：encode 输入是 `ctx.work.buf` 的只读视图；各 encoder 只读，不写。flatten 已在共享段完成（多输出时代码现状：flatten 逐输出边界已由 M4 处理；设计保持"共享段一次"）。
- **ertex 对象独立**：`pt.enc->encode()` 现状每 target 调一次、encoder 实例由 registry 构造（无状态/可共享）；并行时每任务使用独立 `EncodeRequest`，无共享可变状态。
- **metawrite**：每个输出路径独立；Exiv2 写不同文件并发安全（外部路径不同；Exiv2 无共享全局写状态）——实现时用单测/TSan 验证；若发现库级全局态，则 metawrite 退化为"任务内完成后串行队列"，encode 仍并行。
- **冲突解析**：`plan_targets` 在解码前完成（现状即如此），输出路径已定；`reserved` 只在文件终态后按成功输出登记（现状），并行不影响批内 rename 序号确定性。
- **mtime**：仍全文件一次（成功输出逐个 sync，现状）。
- **取消**：每个任务在 encode 前后检查 cancelled；取消 → 后续 target 不再启动；已编码未 metawrite 的候选按现状处理（不写半成品；编码产物删除与否沿用"取消不落盘"）。
- **失败隔离**：单 target 失败不影响其它并行 target（现状语义）；聚合终态由 `verdict_of_rows` 单源计算。
- **进度事件并发**：ProgressMux 已有数据锁+事件序列锁（`progress.h:167-180` 的 R-170 口径）；并行时事件会交错，但每输出单调、`overall_frac` 由 mux 统一兜底；实现需补"多线程并发 bind/tick/emit"单测（TSan）。
- **线程预算**：并行任务不再各自开线程（它们是"worker 线程内的顺序子任务"），因此不破坏 `ΣE≤T`；`E` 仍按文件级分配下发到每个 encoder。

#### 4.4.2 预期收益（基于实测）

| 场景 | 现状 | B1 后预期 |
|---|---|---|
| 1 文件 4 格式（jpeg/webp/jxl/heif）无评分 | 20.1s（Σencode） | ~13–14s（webp 12s 主导，其余并行） |
| 1 文件 2 格式 + 评分 | 36.5s（0.99 核） | ~17–20s（encode 并行 + 评分池并行） |

#### 4.4.3 编码器缓冲预算（新增估算表，实现期实测校准）

并行任务需要额外内存（各 encoder 内部缓冲）。设计：
- 新增常量表 `kEncoderFlightBytesPerPixel[format][bitdepth]`（初值按经验：x265 10bit ≈ 24–48B/px、libjxl ≈ 8–16B/px、SVT ≈ 16B/px、WebP/JPEG/OIIO ≈ 4–8B/px；以实测 RSS 校准后进 `enc_common`）。
- 每任务启动前 `budget.acquire(flight_bytes)`：拿不到 → 该任务**退回串行**（仍可完成，只慢）；预算容量不足时不失败。
- `budget report` 增加 `peak` 读数（已有）；不改变 `2×frame` 契约（文件基线预算）。

### 4.5 输出链路其它卡顿（A4/C8/C9）

1. **双重 probe 消除（C8）**：`FileEntry` 已有 `ImageInfo info; bool probe_done`（`pipeline.h:64-70`），但 pipeline 仍重新 probe（`scheduler.cpp:23-26` 注释自认"冻结接口无 spec 字段"）。设计：
   - `FileEntry` 末尾加性追加 `ProbeOutcome probe;`（完整 probe 结果，含 OIIO spec/ICC 路径/元数据 plan 所需信息）；scheduler 探测后回填；pipeline 按 `fe.probe_done` 复用；缓存失效语义 = 同一次 run 内不变（文件被外部改写属于用户竞态，如实记录，不处理）。
   - HEIC 输入 pre-decode 目标 ≤1.6s（原设计 ≤1.0s；W1-T1 实测剩余单次 probe≈1.45s 属 OIIO/libheif 固有，≤1.0s 需跨 run 持久 probe 缓存——列为 P2，见 D-3）。
2. **exiv2 元数据快路径（C9，D-2 修订）**：现状"整文件拷贝到临时副本→Exiv2 改写→rename"（`metadata.cpp:856-912`）。实测/源码事实：exiv2 承载格式（JPEG/PNG/TIFF/WebP）的编码器**故意不内嵌 EXIF/XMP**，即使无任何编辑也必须写回源元数据，跳过=丢元数据（金样会红）。落地口径：
   - 保留 W1-T1 已实现的"入口判定 + 命中日志"安全子集：仅当**源本身无元数据且无手术**时跳过写回（实测 metawrite≈0.01ms）；其余一律走 R-002 原子写。
   - 大幅节省（0.84–1.40s/大图）需"编码器内嵌元数据"或"免拷贝原子写"两条新路径之一 → 登记为 P2 新任务（需改产物字节/新 Spike，不在 W1 范围）。
   - 有手术时行为与现状逐字节一致（回归语料含元数据手术用例）。
3. **jxl 编码长尾心跳（C15）**：libjxl 回调在收尾压缩段停更（实测 4.28s 静默）。设计：ProgressMux 的 `synth_active` 判定扩展为"回调停更 >300ms 且编码未完成 → 合成心跳"（只发心跳事件、不虚增 frac；`synthetic` 标识如实）；HEIF/AVIF/WebP 合成进度路径不变。
4. **日志限流**：debug 级每行日志点全部审查（不止 color 路径）；统一"每文件每 key 每阶段 ≤N 条 + 超限汇总一行"。

### 5.4 刷新时序（C15）

**结论：不是把 60ms 改小就能解决**（静默期没有数据）。四层：

1. **双通道 flush**：`dirty_state`（状态翻转：阶段切换/评分开始/输出完成/评分到达/终态）→ `QTimer::singleShot(0)` 立即刷一帧；`dirty_progress`（数值/百分比）保持 60ms 合并。
2. **dirty-row 渲染**：`RunState` 增 `std::vector<bool> row_dirty`；`apply_progress/apply_terminal` 只标对应文件；flush 只渲染脏文件 + 总览（O(1) 读数）；`begin_run/reset/end_run/set_tokens` 全量。避免大批量 O(总行数)/60ms 重绘（500 文件×3 格式≈3 万控件）。
3. **"评分中"中间态**：格式行收到 Encode 1.0（on_output_encode_done 强制发点）且未收到 OutputDone → 显示"评分中"；评分关/极快时同批事件合并，不会闪现。
4. **事件消费**：新增 `FileState::OutputDone` + `FileEvent::output`（§4.6），UI 立即结算行（大小/耗时/原因/评分）；文件终态幂等校准。

#### 6.1.2 自动语义（用户："默认根据 level 分块，level 进入主配置"）

```
输入：Level L（0=自动）、图像 w×h、色度 c、profile P
若 L > 0：
    M = MaxLumaPs(L)；D = floor(sqrt(8·M))      # H.265 表，x265 4.3 level.cpp
    若整图（8 补齐后）满足 w8*h8 ≤ M 且 w8,h8 ≤ D  → 单图（grid 不启用）
    否则 → grid 自动：按 6.1.3 求 tile 尺寸，使每 tile 满足 (tw8*th8 ≤ M) 且 (tw8,th8 ≤ D)
若 L == 0（自动）：
    整图若在 HEVC 最高 Level 7.2 容量内（MaxLumaPs 142,606,336；D≈1067）→ 单图
    否则 → grid 自动：基准 1024×576 tile（每 tile x265 自动 Level）
tile 数 = ceil(w/tw) × ceil(h/th)，要求 rows*cols ≤ 65535
```

- **默认配置零变化**：Level=自动 + 常规尺寸 → 单图（与 HEAD 相同）；只有"显式低 Level 装不下"才自动分块（与 HEAD M9 的救火一致），但用户现在可以在主配置区看到 Level 并理解原因。
- **grid=总是**：无显式 Level 时按 Apple 基准 1024×576（每 tile 自动 Level，x265 实测 L3.1）；用于对齐 Apple 参考结构。
- **grid=关闭**：超 Level 直接中文预检错误（点明样本数/上限/最小可行 Level/两条出路：提高 Level 或启用自动）。
- 语义说明（UI note）：**Level 约束的是每个 tile，不是整图**（grid 输出是派生图）——行内 note 显示完整规划。

#### 6.1.3 tile 尺寸推导（自动）

```
基准：tw0 = align_down(min(w, 1024), 8)；th0 = align_down(min(h, 576), 8)
若 L > 0 且 (tw0*th0 > M 或 tw0 > D 或 th0 > D)：
    在 [64, min(w,1024,D)] 内按 8 步进枚举 tw；
    th = align_down(min(h, 576, D, floor(M/tw)), 8)
    取面积最大者；面积相同取 |tw/th − 1024/576| 最小者（继承 M9 A9 规则）
校验：tw,th ≥ 64 且 8 的倍数；(c=420 → w,h 偶数；c=422 → w 偶数)  # MIAF 7.3.11.4.2
```

#### 6.1.4 手动覆盖（高级）

| 情形 | 行为 |
|---|---|
| 值非 8 倍数 | 向下对齐到 8，行内 note「已对齐到 N」（不静默失败） |
| 值 < 64 | 预检错误（最小 64×64，建议自动） |
| 显式 Level 下 `tw8*th8 > M` 或 `tw8/th8 > D` | **预检错误**（点明 MaxLumaPs/D/最大可行 tile + 三条出路：改自动/提高 Level/关闭 grid），不静默降级 |
| 手动 tile ≥ 图像（rows*cols==1） | 降级为单图 + info 日志（grid 1×1 无收益）；同步修订既有单测锁定行为并登记裁定 |
| Level=自动 + 手动 tile | 允许（x265 给每 tile 自动选 Level），行内 note 提示"与 Apple 参考配置不同，iPhone 接受度未验证" |
| alpha | 格式表 `supports_alpha=false`，GUI 不可达；引擎保留防御性拒绝 |
| 奇数尺寸 + grid（MIAF 奇偶） | **warn**（保持既有 801×601→grid 行为与单测；error 需另立裁定） |

UI 行内 note 显示规划摘要：`每 tile 1024×576 · 网格 2×3 · 每 tile Level 3.1 · 共 6 次编码`（grid 关闭显示"单图（不分块）"）。

#### 6.1.5 验收（§12）

- 默认配置 HEIF 产物 SHA256 与 HEAD **零变化**（Level=自动+常规尺寸）。

### 6.2 需求 3：HEVC profile 补齐（C18/C19）

#### 6.2.1 标准事实（设计依据，如实标注）

- HEVC profile 由 VPS/SPS 的 **profile_tier_level** 表达：idc + compatibility flags + **48 位 constraint flags**。非 RExt（idc=1/2/3）其余 44 位保留 0 → **Main 10 Still 没有独立 PTL 位**；RExt（idc=4）的仍像变体 = `idc=4 + intra=1 + one_picture_only=1 + 对应 bitdepth/chroma upper-bound flags`（x265 `entropy.cpp:725-790`、`level.cpp:68-113`）。
- x265 只能写 idc=1/2/3/4（`determineLevel` 全部分支）；"Main 4:4:4 10 Still Picture" 不是独立 idc，而是 idc=4 + 上述约束 → **HEAD 的 `Rext444_10` 已产出该信号**（SPS PTL 实测：idc4/444/10/intra=1/one_picture=1）。
- x265 的日志把它叫 "Main 4:4:4 10 Intra"（`level.cpp:290-311` 只在 444 8-bit/16-bit 分支打印 Still Picture）——日志命名遗留，不代表标准无此 profile。
- **hvcC 丢 still 标志**：libheif 生成 hvcC 时跳过 48 位 constraint（`hevc_boxes.cc:628-630`），实测所有产物 hvcC constraint 字节=0；因此现有"hvcC 回读校验"无法验收 still 变体 → **必须新增 SPS PTL 解析**（从 hvcC 内嵌 SPS NAL 原始字节解析，去防竞争字节）。

> 规范命名复核（开放风险 R-2）：本设计依据 LKML 指向 H.265 (2019-06) A.3.3 + 专利转述 + x265/libheif 实现与实测，无法在本环境直接读 ITU PDF；落地前需由能访问规范的复核者确认 "Main 4:2:2 12 Still / Main 4:4:4 12 Still / Main 4:4:4 Still" 名称准确集合。设计采用**保守映射**：新增档位以"信号 + 官方名（待复核）"双写，UI tooltip 保留信号描述。

#### 6.3.1 事实（运行时内省 + 上游源码）

#### 6.3.2 设计

**HEIF（不 patch 依赖）**：
- `tune` 行 choices 扩为：`psnr / ssim / grain / fastdecode / animation（仿真）/ zerolatency（置灰）/ vmaf（置灰）`。
- `animation` 仿真：插件 tune 仍用默认 `ssim`，在用户透传**之前**注入 `x265:psy-rd=0.4, x265:aq-strength=0.4, x265:deblock=1:1`（实测编码 OK；与 x265 tune=animation 的 still 相关效果等价，tooltip 注明"近似仿真"）；用户若在高级区显式覆盖这些键 → 以用户为准（后写覆盖）。
- `zerolatency`：单帧无实际效果（只改线程/GOP 类）→ 置灰 + 原因；`vmaf`：x265 4.3 空实现（`param.cpp:710-713`）→ 置灰。
- `fast-decode`/`zero-latency` 别名归一化，不单列。
- 机制解释进 tooltip：插件在 preset/tune 之后强制 `aq-mode=1, psy-rd=1.0, psy-rdoq=1.0`，故 x265 tune 的 psy/AQ 部分被覆盖；残留差异 = psnr 的 aq-strength=0 / grain 的 sao=0 / fastdecode 的 deblock+sao=0。实测分数：psnr 93.64 / ssim 92.83 / grain 91.89 / fastdecode 92.77（1600×1200 10bit 420 q75）。

**AVIF/SVT**：值集已全，只补中文标签与联动提示（`iq`/`ms-ssim` 会把 BRC 从 CQP 切到 CRF，`encoder_svt.cc:873`）。

**AVIF/libaom**：`tune` choices 扩为 `auto / psnr / ssim / iq / ssimulacra2 / vmaf_saliency_map`；原生 4 值走插件，新增 2 值由引擎内部走 `aom:tune=<v>` 透传（**不新增 `aom:tune` 目录行**，避免双控件；aom 插件 custom options 在全部内置控制之后应用，最后生效）。不可用值（vmaf/butteraugli/cdef-dist）置灰 + tooltip 原因。

**暴露方案单源**：
1. 运行时内省为首选（`heif_encoder_list_parameters`）；
2. 静态事实表兜底"插件不支持但库支持/可仿真"的值（`enc_common` 内新表：后端 → 值 → 类别(原生/仿真/置灰) → 引擎处理 → 原因）；
3. 一致性探针：单测/启动断言"下拉可选值 ⊆ 运行期接受集 ∪ 仿真表"，防依赖升级静默漂移；
4. 不可用值呈现：置灰（透明度优先）而非删除（"不撒谎"且可解释）；`vmaf` 等历史值保留位置。

**验收**：对每个可选值编码一次（结构可解 + sidecar），置灰值不可选；tune=animation 产物可解码、分数/体积与 ssim 基线有差异（证明仿真生效）；预设往返不变。

## 9. 需求 11：自适应参数调整（C24）

> 用户裁决：策略 = 行式 DSL 文本，**GUI 无编辑器，只存在格式预设文件里**；最多轮数也在预设文件中配置；默认语义 = 目标 ≥90、最多 8 轮、未达标输出最后一轮、取消丢弃。
> 定位：把"评分 ≥90"变成**可执行、可复算、可审计**的配置质量策略；默认关闭，启用后仅在显式携带策略的格式输出上生效。

### 9.1 执行语义（必须无歧义，逐条可测试）

1. **启用**：格式预设 `adaptive.enabled=true` 且 `policy` 非空；载入预设后格式卡显示只读摘要（`含自适应策略：目标 90 / 最多 8 轮 / 3 个阶段` + `停用` 开关）；未载入预设/策略为空 = 关闭（默认）。
2. **作用域**：每 (文件 × 输出) 独立执行；只改本输出的参数（`ParamSet` 副本）；策略不得改全局项（color/bitdepth 属于格式级，禁止）。
3. **一轮** = 应用参数 → 编码到候选临时文件 → 评分 → 决策；允许的编码参数沿用现有规则/预检；每轮目标路径 = `atomic_temp_path(最终路径)`（同目录唯一名），**不写元数据**（评分只看像素）。
4. **终止**：
   - 成功：`score >= target`（默认 90，浮点按 ≥ 判定）→ 立即终止后续阶段；
   - 阶段耗尽：进入下一 stage；无下一 stage → 失败终止；
   - `max_rounds`（预设文件内，1..32，默认 8）触顶 → 失败终止；
   - `plateau`（可选，连续 2 轮改善 < 阈值）→ 失败终止；
   - 取消/编码失败/预检失败/评分不可用 → 按 §9.4 语义。
5. **输出**：失败终止输出**最后一轮成功编码**（用户示例口径；`output last`）；P1 可选 `output best`（历史最高分，需保留候选文件）。选定候选 `commit_temp_file` 到最终路径 → 再走既有 metawrite/mtime 段（顺序：encode→score→metawrite 仅对最终文件一次，与现状一致）。
6. **取消**：轮间检查取消 → 删除全部候选、该输出 `Cancelled`、不落盘（与现状取消语义一致）。
7. **评分不可用**（回读失败/尺寸不符/取消）：默认 `on_metric_unavailable stop`（停止迭代，输出当前最后成功轮；metric 记 Unavailable）；可选 `fail`（该输出失败，error="adaptive: metric unavailable"）。
8. **评分开关关系**：自适应必须评分 → 即使设置里 `quality_score=false`，启用自适应的输出仍计算评分（UI 摘要注明"自适应需要评分"）；非自适应输出不受影响。
9. **确定性**：不改变编码器线程策略（用户裁决）；同输入同策略同配置 ⇒ 同结果（沿用既有回归/确定性口径）；策略文本 SHA256 前 16 进日志便于比对。
10. **线程/并行**：自适应在 worker 线程内串行执行（每轮串行）；不同文件/不同输出之间仍可并行（文件级并行/多格式并行照常），与 §4 的并行模型正交。

### 9.2 策略语言（行式 DSL v1）

**语法（EBNF 摘要）**：

```ebnf
policy      = { option } , { stage } ;
option      = "version" INT                 (* 省略=1 *)
            | "target" NUMBER               (* (0,100]，默认 90 *)
            | "max_rounds" INT              (* 1..32，默认 8 *)
            | "output" ( "last" | "best" )  (* 默认 last；best=P1 *)
            | "on_metric_unavailable" ( "stop" | "fail" )  (* 默认 stop *)
            | "plateau" NUMBER ;            (* 0=关；>0=连续 2 轮改善<阈值即止 *)
stage       = "stage" IDENT NL { action } ;
action      = "search" KEY "from" VALUE "to" VALUE "step" NUMBER
              [ "method" ( "linear" | "bisect" | "exp" | "greedy" ) ] [ "max_rounds" INT ]
            | "set" KEY VALUE ;
KEY         = 目录内参数键 | "profile" | "chroma" | "tech"  (* 伪参数 *)
VALUE       = NUMBER | true | false | ENUM_NAME | "字符串" ;
IDENT       = [a-z][a-z0-9_-]{0,31} ;
comment     = "#" 到行尾 ;
```

- 缩进不是语义（`stage` 行开始新阶段），空行/注释自由；**行号+列号错误定位**（`AdaptiveError{line,col,code,message,hint}`）。
- 大小写：关键字小写；枚举值按参数目录 choices 匹配（中文显示名或引擎值均可）。
- 规范化渲染：解析→渲染（注释保留可选）→ 再解析 = 同一 AST（幂等）；落盘为原始文本（人类可编辑），日志记录规范化 SHA。

### 9.3 AST / 机器面（导入用，不落盘）

- `AdaptivePolicy{version,target,max_rounds,output,on_metric_unavailable,plateau,stages[]}`；`Stage{id, actions[]}`；`Action{kind:Search|Set, key, from/to/value, step, method, max_rounds}`。
- JSON Schema 草案随实现落 `docs/schemas/adaptive-policy.v1.schema.json`；**导入接受 JSON AST**（脚本生成），导出仍为 DSL 文本（避免双真源）。
- 校验错误码表（实现期细化，≥22 条）：未知 option/stage/action、target 越界、max_rounds 越界、search 目标非数值、set 值类型不符、枚举值非法、参数在禁止表、stage 空、方法名非法、行号定位等；中文可操作。

### 9.4 允许/禁止目标键（正交性核心）

| 类 | 键 | search | set |
|---|---|---|---|
| 数值质量参数 | `quality`（heif/avif/webp/jpeg）、`distance`（jxl/jpeg）、`x265:crf`、`x265:qp`、`aom:cq-level`、SVT `qp` | ✔ | ✔ |
| 枚举/布尔/文本 | `chroma`、`preset`、`tune`、`epf`、`gaborish`、`dots`、`patches`、`modular_predictor`、`modular_group_size`、`color_transform`（JXL） | ✘（错误：不可搜索） | ✔ |
| 伪参数 | `profile`（HEIF/AVIF 档位名或编号）、`tech`（P2，默认禁止）、`chroma` 视为结构键 | ✘ | ✔（切换后重跑整套校验） |
| **禁止表（硬拒绝）** | `lossless`、`resampling`、`upsampling_mode`、`intensity_target`/`min_nits`/`relative_to_max_display`/`linear_below`、`keep_invisible`、`noise`、`photon_noise`、`disable_perceptual_heuristics`、`expert_options`、`codestream_level`、`buffering`、`output_mode`、`frame_name`、`intrinsic_size`、位深、全局项、`__` 保留键（除 profile 映射） | — | — |

（W3-T3 落地口径：set 允许面 = 该格式参数目录键 − 禁止表；search 白名单 6 键 `quality/distance/x265:crf/x265:qp/aom:cq-level/qp`；`output best` 在 P1 前显式拒绝。**理由**：迭代期间只有策略声明的参数可变，评分参考（源图量化样本/色彩/位深/分辨率）恒定；禁止表排除"改评分口径/改分辨率/改容器语义"的键，保证"优化"语义正交、可解释、可复现。

### 9.5 搜索算法与成本

| method | 候选序列 | 轮数上界 |
|---|---|---|
| linear（默认） | `start + dir*k*step`（dir=sign(to-from)），钳到参数域与端点 | ≤16/阶段 |
| bisect | 端点已知"差/好"侧时按分数二分，直到区间 <step 或达标 | ≤18/阶段 |
| exp | 步长×factor（默认 1.5，上限 4） | 受 max_rounds |
| greedy | 朝目标步进；无改善则步长减半，低于最小步长停止 | 受 max_rounds |

- **三层上界保证终止**：全局 `max_rounds`（≤32）+ 每 stage 上界（≤18）+ `set` 每个 1 轮；`plateau` 额外提前终止。
- **成本模型**（实测）：2MP 每轮 encode 0.5–1.0s + score 0.63–1.03s ⇒ 每轮 1.3–1.8s；23MP 每轮 encode 3–6s + 评分（流式后 1.5–3s）⇒ 每轮 5–9s。`max_rounds=8` 最坏 ≈ 8×单轮。
- **UI/日志披露**：格式预设摘要显示"策略最多 N 轮（预计 ×M 耗时）"（M 用单轮估算，无法估算时显示"—"）；逐轮日志/侧车可复算。

### 9.6 执行器（pipeline 内，候选文件策略）

```
stage_encode_loop 内（policy 非空时替换单次 encode 段；空策略 = 旧路径逐字不变）
for stage in stages:
    if rounds >= max_rounds: break
    if stage is Set:
        next = base; for kv: apply_pseudo_or_param; validate_round
        encode_round_and_score(next) → 记录/更新 last
        if score >= target: success; break
    else:  # Search
        ladder = make_ladder(base[key], from, to, step, method)
        for value in ladder:
            if cancelled: cleanup(); return cancelled
            if rounds >= max_rounds: break
            next = base; next[key]=value; validate_round
            cand = encode_round_and_score(next)
            update last; rounds++
            if score >= target: success; break
        # 阶段耗尽进入下一 stage
finish: commit(selected = last 或 best) → 既有 metawrite/mtime
```

- `encode_round_and_score`：与现有 encode 段**同口径**（同一 encoder/参数装配/预检），唯一差异 = `target.out_path` 指向候选临时文件；评分复用评分链路（自适应路径**同步等待**本轮分数）。
- 评分链路复用：非自适应输出走异步评分池（§4.2）；自适应轮次走"同步评分"（每轮必须拿到分数才能决策），实现为 `ScorePool::run_sync(task)`（池满时排队，仍受 max_rounds 约束）。
- 候选管理：最多保留 `current` + （`output best` 时）`best` 两份；结束 `commit_temp_file` 选定者、`discard_temp_file` 其余；取消清理全部。
- 进度：每轮结束发 `ProgressInfo`（`adaptive_round/adaptive_max` 加性字段），overall 不虚增；运行页显示"自适应 3/8"；评分期心跳（C15）。
- 日志（info，仅启用自适应时新增）：
  ```
  [info] [pipeline] adaptive round {src=… out=… output_index=0 round=2 stage=crf-up
          key=x265:crf value=14.0 score=91.2 state=ok bytes=… encode_ms=… metric_ms=… decision=met}
  [info] [pipeline] adaptive summary {src=… rounds=3 target=90 selected=round2
          policy_sha=… final_score=91.2 overhead_ms=…}
  ```
- sidecar 加性（仅启用时）：`"adaptive": {policy_version,target,max_rounds,output,rounds:[…],selected_round,final_score,reason}`（`tests/golden/SCHEMA.md` 加性节，M8-C13 先例）。

### 9.8 语义完备性检查清单（逐项必须成立）

| 性质 | 保证方式 |
|---|---|
| 正交性 | 禁止表 + 每轮 `validate_round` + 评分参考维度冻结 |
| 无歧义 | stage 只有 Search/Set 两型；方向由端点序定义；`current`=运行配置值；`last/best` 二选一 |
| 可终止 | 三层轮数上界 + plateau + set 有限 |
| 可复现 | 策略 SHA + 逐轮参数/分数/字节进日志与侧车；同配置同结果（不碰编码器线程策略） |
| 幂等 | 每次从运行配置出发（不是隐式状态机）；重复执行同策略同结果；日志/侧车只追加 |
| 可观测 | 逐轮 info 日志 + sidecar + 运行页"自适应 N/M" |
| 失败语义 | 编码失败/评分不可用/预检非法/取消四类分别定义，绝不静默 |
| 边界 | 无损/评分≈100 ⇒ 立即成功（0 轮）；<8×8/回读失败 ⇒ Unavailable 路径；单值 stage=1 轮 |
| 隔离 | 每 (文件×输出) 独立；候选文件名含 out index/round；不改其它输出 |
| 成本可控 | max_rounds + UI 披露 + 日志实际耗时；不做隐藏降级 |

## 16. 未决 / 待确认项（如实）
