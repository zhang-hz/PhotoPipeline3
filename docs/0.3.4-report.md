## 3. 归因一：门禁为什么没有发现（Q2）

**结论：不是判据被放宽、不是门禁没跑，而是判据面存在结构性盲区——全部 UI 判据都跑在
offscreen 平台，而本缺陷只存在于真实 Windows 窗口平台。**

1. **每道门禁都严格执行且全绿**：格式 0 diff、tidy 棘轮持平、ctest 全绿、金样 20/20、回归
   zero diff、`--ui-smoke` 冻结行逐字——0.3.3 发行前的读数逐条真实。金样走 `--dev` harness
   （引擎面，不建真窗）；`--ui-smoke` 与 make_winzip E-2 显式 `QT_QPA_PLATFORM=offscreen`；
   ctest 是纯函数单测（UI 类不进 ctest 是既有口径）。**没有一道判据启动过真实 qwindows 窗口。**
2. **offscreen 对该缺陷是盲的**：`frameless.cpp` 的 Windows 收口整段以 `IsWindow()` 短路
   （代码注释明言「offscreen 平台的 winId() 不是真窗口 → 整段跳过，--ui-smoke 行为不变」）；
   递归建窗由 `CreateWindowEx` 同步投递 `WM_NCCALCSIZE` 触发，offscreen 平台没有这条消息链。
   实测佐证：`QT_QPA_PLATFORM=offscreen` 启动 0.3.3 坏件 = 0 窗口风暴、进程正常。
3. **真机验收不在门禁内且未签收**：UX-7/UX-13（真无边框 + Win11 圆角）的验收形态是
   「真机验收清单待人工逐项签收」（CHANGELOG [0.3.3] 自己标注），既非机械化判据、也未闭环。
4. **补缺**（M7R24-2）：E-3 真机启动探针进 make_winzip 门禁（CI 每次打包必跑），断言
   「可见主窗 + 顶层窗口数不超阈（递归建窗风暴守卫）+ 进程存活」；坏件阳性对照被拦（上节）。
   同类缺陷（真机建窗/窗口不可见/启动风暴）自此有本地与 CI 同源的机械化判据。

## 4. 归因二：开发测试为什么没有发现（Q3）

**结论：开发期的 GUI 验证通道与发布形态不同构——验证物是 offscreen 截图走查，发布物是
真实 qwindows GUI；改动合入后没有任何人在真机上启动过 0.3.3。**

1. **开发验证通道清单**：`--ui-smoke` 走查、`--dev` harness、GUI-R2 渲染像素探针、金样——
   全部 offscreen / 引擎面。M7-WP5 的 frameless 改动验收也走这些通道 + 渲染截图（temp_bug.png
   对比「原生 chrome 是否消失」是渲染面取证，不是真机启动取证）。
2. **时序与风险低估**：`winId()` 从「消息类型判断之后」挪到「之前」看似无害（返回值同为
   句柄），实际把「过滤器可重入建窗」这个隐蔽面打开；code review 与静态分析都看不出
   （tidy 不跨 Win32 消息时序），**唯一防线是探针**——而当时没有真机探针。
3. **流程侧直接责任点**：真机验收清单标注「待人工签收」后**未签收即发行**。CHANGELOG 如实
   标注了「待人工签收」，但未设为发行阻断条件；本次把「真机可启动」升格为门禁（E-3）后，
   这类「标注了但没人做」的清单有了机械化兜底。
4. **20min CI 预算不是原因**：E-3 实测秒级；缺的从来不是预算，是判据形态。

  归因全文入提交正文。
- **门禁 5 → 6**：判据只增不减（M7R24-2）。
- **冻结面零改动**：frameless 非 PP-FROZEN 面；`--version` 单行格式、SMOKE/UI-SMOKE 冻结行、
  `tests/golden/SCHEMA.md`、夹具与金样全部逐字未动。

## 6. 未覆盖 / 未决项（如实）

- **UX-7/UX-13 真机视觉清单仍待人工签收**（圆角、三钮命中、缩放带、Mica 等）：E-3 只保证
  「能开、窗口可见、无建窗风暴」，不覆盖视觉逐项。
- **0.3.3 Release 资产未撤**：发行纪律「tag 资产挂载后不可移动」，处置 = README/CHANGELOG
  标注「坏件请用 0.3.4」；若需在 Release 页挂公告横幅，属对外动作，待用户裁定。
- **Linux 侧**：同一 frameless 代码在 Linux 走 `startSystemMove/Resize`（Qt 路径，无
  `WM_NCCALCSIZE`），无此缺陷面；E-3 为 Windows 探针（`make_winzip` 本就 Windows-only）。
  AppImage 侧无对等「真机启动」探针，Linux 桌面远端会话下留待后续。
