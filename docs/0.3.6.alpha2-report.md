## 1. 交付内容

### 1.1 JXL 有损 VarDCT 修复

- 根因：`enc_jxl.cpp` 把「有 ICC」推导为 `uses_original_profile=true`，导致**所有有损 VarDCT**
  落入 libjxl 非 XYB 有损路径（上游 libjxl #4552）：质量-距离倒挂、体积暴涨。
- 修法：有损 VarDCT 恒 XYB（`uses_original_profile=false`；ICC 照常嵌入，解码端可换回原 profile）；
  显式 `uses_original_profile=true` + 有损 VarDCT → 明确失败（不产坏件）；无损/Modular 语义不变。
- 新增 `tests/unit/test_jxl_original_profile.cpp`（42 断言；直接解 JXL 码流头，不经 OIIO 转述）。

### 1.2 HEIF 真实档位 / Level / grid 配置矩阵

- 档位：12 个真实 HEVC 信号 + 自动（Main Still Picture idc3 / Main idc1 / Main10 idc2 /
  RExt 4:2:0·4:2:2·4:4:4 × 8/10/12 idc4）；非原生信号由编码器内部注入 x265 参数；
  编码后 hvcC 回读校验 `profile_idc/level_idc/chroma/bit_depth`。
- Level：x265 4.3 全表（1.0–7.2，含 6.3/7.0/7.1/7.2）；按 **8 像素补齐后的 MaxLumaPs + 宽高上限**
  做编码前预校验，非法给中文可操作错误；合法组合编码后回读 `level_idc` 校验。
- 有损 HEIF grid：`__heif_grid`（0 关 / 1 总是 Apple 式分块 / 2 自动，缺省）；tile 以 Apple
  1024×576 为基准、按显式 Level 8 对齐收缩；逐 tile nclx+ICC、通道感知 clamp 切片、alpha+grid 明确拒绝；
  无损大图现有 2048-tile grid 路径不变；**默认（无显式 Level）HEIF 产物与旧二进制 SHA256 完全相同**。
- `src/codecs/heif_capability.*`（新增纯核）：Level 表 / 拟合 / grid 规划 / hvcC 解析。
- `tools/heif_matrix_check.py`（新增）：穷举矩阵验证器（合法性模型 + 编码 + BMFF/hvcC 结构断言 +
  `iinfo` 解码 + JSONL/MD 证据）。

### 1.3 测试与门禁工程

  - A7/A8 新增源文件/单测/矩阵工具（pp_core 以 glob 自动收编）。

  - JXL 有损 VarDCT 产物由非 XYB 改为 XYB（体积/评分按预期变化；回归已归因）；
  - HEIF 档位 `Main10` 现写 idc=2（旧实际 idc=4）、`Main` 现写 idc=1（旧实际 Main Still idc3）；
  - 大图 + 显式低 Level：默认自动分块而非失败（关闭 grid 则给准确错误）。
- 回归基线仅版本行换锚，未重播种；JXL 预期产物差异与已知 runner 形状差异不计入发行判据，
  以 CI 双平台 zero diff 为准。

## 4. 未覆盖/未决（如实）

1. **GUI 无显式「总是 Apple grid」行**：当前通过「显式低 Level → 自动 grid」或保留键
   `__heif_grid=1` 使用；加 UI 行会触碰 `--ui-smoke` 冻结截图，需用户确认后另起。
2. **iPhone 真机接受度未验证**：本段只证明「软件能产出合法、本地可解码的 HEIF/HEVC 配置」；
   真机硬解/Photos 接受度需真机 VT 强锁 + AirDrop 测试（工具 `super/iphone-test/vt-probe/`）。
3. **Windows Photos 16-bit JXL 颜色问题与本次修复无关、仍存在**：Microsoft WIC JXL 1.2.50.0
   对 16-bit JXL 只暴露 `64bppRGBHalf`、0 颜色上下文且 `ColorManageToSRgb` 为 no-op（8-bit 正常）；
   这是 viewer/WIC 缺陷，不是本仓文件缺陷（`build/analysis-wic/results.md`）。
4. **AVIF 未纳入矩阵**；T1 单图 Level 仅抽样 9 例；grid 低 Level 收缩仅抽样（L2.0 207 tiles 一例）。
5. 显式 Level + CRF 的 x265 自动 VBV（输出非确定）未加 product warning；显式 Level + `x265:qp`
   （CQP）由 x265 拒绝但未翻译文案（A15，后续小项）。
6. `__x265:total-frames`/`__x265:keyint` 只读行 label 仍写「恒为 1（插件固定）」，与 Main10/Rext420_8
   信号时内部置 2 不一致（文案批次）。
7. 单次大 grid 编码空闲后首跑可能有一次 ~150s 级抖动（与 profile 无关，verdict 不受影响；
   T1 L3.1 常规 11–20s）。
8. 本机未构建 release（非 dev）树；release 树的 ctest/金样与 winzip/AppImage/`--version` 断言由
   CI 双平台（main-full #102 10/10、release #22 7/7，均全绿）复核（见 §2.5）。
