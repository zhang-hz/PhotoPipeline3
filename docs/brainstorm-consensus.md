# PhotoPipeline — 需求共识文档（头脑风暴结论）

> 状态：**需求共识已达成；设计阶段已完成，见 `design.md`（本文档 §9 记录设计期修订）。**
> 形成方式：4 轮批量交互式提问（架构根基 → 格式与质量细节 → UX/日志/分发 → 收尾澄清）。
> 本文档只记录"是什么"与"为什么"，不包含架构与代码设计。

---

## 1. 产品定位

一句话：**批量像素级转码器 + 元数据手术台**。

- **像素搬运工**：解码 → 色彩管理 → 编码，中间不加料
- **元数据手术台**：任意 EXIF/XMP 编辑、时间偏移（含时区语义）、GPS 写入（地图选点）
- **批量流水线**：文件级并行 + 点位极丰富的文本日志

它**不是**：图像编辑器、图库管理器、看图软件、RAW 处理器。守住这条边界本身就砍掉了大部分复杂度。

## 2. 不可协商的核心原则

1. **禁止降级**：内部处理禁止任何形式的质量降级；能浮点不用整数——内部管线全程 float32。
2. **高质量 + 高性能**：只用各格式最强的编码器实现；全功能构建，禁止精简依赖。
3. **全参数暴露**：所用库的全部参数进入 GUI 可配置（核心参数置顶、高级参数折叠展开；使用滑条/下拉/复选等普通交互控件，不用表格控件）。
4. **小而美**：砍掉一切与"转码 + 元数据"无关的功能；以最快速度完成开发。
5. **无额外图像处理**：除 EXIF 方向旋转（开关式，默认开）外不做任何像素变换。

## 3. 已锁定决策

### 3.1 平台与技术栈

| 项 | 决策 |
|---|---|
| 目标平台 | **Windows 11 25H2+（唯一一等平台，可用最新系统特性）**；Linux x64 |
| GUI | Qt 6 最新 LTS + C++23，**Qt Widgets**（非 QML） |
| 视觉 | Qt 自带 Windows 11 (Fluent) 风格 + **Mica 材质**（DWM SystemBackdrop API；因起点为 25H2，恒可用） |
| 解码 | **OIIO** 统一读入全部输入格式 |
| 编码 | **直连原厂 API**：jpeg-li（JPEG）、libjxl（JXL）、libheif+x265（HEIF）、SVT-AV1 + libaom 双后端（AVIF）、libwebp（WebP）；**PNG/TIFF/BMP 走 OIIO 输出**（GUI 暴露 OIIO 该格式的全部输出参数） |
| 色彩 | lcms2（浮点变换） |
| 元数据 | Exiv2 |
| 日志 | spdlog（文本文件输出） |
| 界面语言 | 中文 v1 + Qt Linguist i18n 架构预留（后续加语言零重构） |
| CLI | 不做；但管线与 GUI 强分离，日后低成本添加 |

### 3.2 输入格式（全量）

TIFF、PNG、JPEG、JPEG XL、HEIF/HEIC、AVIF、WebP、BMP、GIF、TGA —— 全部经 OIIO 解码（HEIF/AVIF 解码需 libde265 / dav1d / libaom）。

**不做** RAW / DNG。

### 3.3 输出格式（8 种）

| 格式 | 路径 | 说明 |
|---|---|---|
| JPEG | 直连 jpeg-li | libjxl 团队的 JPEG 编码器，标准兼容、同画质体积更小 |
| JPEG XL | 直连 libjxl | 全部编码器参数暴露 |
| HEIF | 直连 libheif + x265 | 接受 GPL（见 §7） |
| AVIF | 直连 libheif + SVT-AV1 / libaom | 双后端作为参数可切换 |
| WebP | 直连 libwebp | 含 sharp_yuv 等 |
| PNG | OIIO | 暴露 OIIO 全部 PNG 输出参数 |
| TIFF | OIIO | 暴露 OIIO 全部 TIFF 输出参数 |
| BMP | OIIO | 无参数，纯输出 |

**GIF 不做输出**：256 色调色板量化 = 强制降级 + 图像处理，与核心原则冲突。

### 3.4 像素管线

- 解码 → float32 像素缓冲 → lcms2 浮点色彩变换 → 编码器目标位深（8/10/12/16，按格式能力）
- **输出位深是显式控件**，默认值 = 高质量档（PNG/TIFF/JXL 默认 16 位；HEIF/AVIF 默认 10 位；JPEG 默认 8 位；jpeg-li 的 12 位 JPEG 支持待核实，见 R3）
- 任何降档（位深降低、无损→有损）在界面上**显式警示**
- EXIF Orientation：开关式，**默认按方向旋转**输出并清除标签
- 有损编码默认 4:4:4 色度采样（具体默认值设计期定）
- **无 HDR**：不处理 PQ/HLG，不做色调映射

### 3.5 色彩空间转换（精简版）

- 目标空间：**sRGB / Display P3 / Adobe RGB (1998) / 保持原样（不转换）**
- 渲染意图：固定**相对比色 + 黑点补偿开启**
- 输入侧任意 ICC（含宽色域源）由 lcms2 浮点管线正确处理
- 输出文件始终嵌入 ICC 档案

### 3.6 元数据

- **任意 EXIF 标签读写**（按标签名/编号选择）；MakerNotes 保留不动（不解析不修改）
- **XMP 读写**（dc、rights、Photoshop 等常用命名空间）；v1 不做 IPTC-IIM
- **时间偏移**：固定 Δ 偏移 + **时区语义偏移**（"原值按某时区解释 → 重写为 UTC/另一时区"的旅行照片修正）；作用字段 DateTimeOriginal / CreateDate / ModifyDate（细节设计期定）
- **mtime 同步**：输出文件修改时间跟随 EXIF 拍摄时间（可开关）
- **隐私导出预设**：一键剥除 EXIF/GPS/XMP（保留 ICC）
- **交互模型：批量规则 + 单文件例外** —— 先对全部/选中文件应用批量规则；双击单文件打开编辑器可覆盖或清除规则；文件列表用徽标标记带例外的文件
- **总流程**：输入文件 → EXIF 编辑（可跳过；批量规则 + 单文件例外）→ 输出设置（全文件一致）→ 运行

### 3.7 GPS 与地图

- 手动批量写入：经纬度 + 海拔 + 方位 + 时间戳；应用到全部/选中文件；支持从现有文件读取坐标；一键清除 GPS
- **地图选点**：自绘轻量 slippy 瓦片地图控件（数百行级），滚轮缩放、点击选点、地名搜索
- 底图提供方：**OSM（内置，免 key，Nominatim 搜索）+ 高德（自备免费 Web 服务 key）**；不接 Google（瓦片无官方拉取方式，ToS 风险）
- **GCJ-02 → WGS-84 自动逆变换**：高德底图选点必须换算后才写入 EXIF，否则有 100–700 米非线性偏差；用户无感
- 联网仅限地图功能；转码全流程离线可用

### 3.8 批量与并行

- **文件级并行**：每个 worker 完整处理一个文件（解码→色彩→编码在 worker 内串行）；线程池默认 = 物理核数，设置可调
- **内存背压：像素预算机制** —— 同时处理的像素总量设上限，按需压低并发（50MP float32 单帧 ≈ 800MB，必须限流）
- 任务控制：**仅取消**（不做暂停/断点续跑/队列持久化）
- 输出目标：**镜像源目录结构**到指定输出根目录；重名冲突策略可选：跳过 / 覆盖 / 自动加序号
- 设计规模：**10–1000 张/批、≤50MP**（文件列表虚拟化、背压参数按此校准）

### 3.9 UI/UX

- 三步式流程界面：输入 → 元数据 → 输出设置 → 运行/进度
- 文件列表：**仅缩略图**（色彩管理正确渲染），不做大图预览、不做编码前后对比
- 参数区：**先选输出格式 → 展示该格式参数**：核心参数置顶 + 高级参数折叠展开；数据驱动生成（加参数 = 加一行数据，代码量恒定）
- 预设：**命名预设（JSON）保存/加载 + 记住上次会话**

### 3.10 日志

- **纯文本日志文件**（无 GUI 面板）；格式简单、点位极丰富：
  - 每次运行：应用与全部库版本、完整参数快照（输出设置 + 每格式参数展开）
  - 每文件：源路径/格式/尺寸/位深/ICC、色彩变换记录、输出路径/位深/字节数/压缩比、**解码/色彩/编码分段耗时**、警告（降档、有损化、元数据丢弃等）、结果
  - 运行结束：汇总（成功/失败/跳过计数、总耗时、总吞吐 MB/s）
- spdlog 分级（trace/debug/info/warning/error）

### 3.11 分发

- Windows：**便携 zip**（免安装）
- Linux：**AppImage**（单文件免安装、自带依赖，即"zip 式"体验）
- 依赖统一用 **vcpkg 全功能构建**（见 R2）

## 4. 明确砍掉的范围（负面清单）

RAW/DNG 输入 · GIF 输出 · 图像编辑（缩放/裁剪/水印/锐化/降噪）· HDR/色调映射 · 大图预览与编码前后对比 · 断点续跑/队列持久化 · IPTC-IIM · Google 底图 · CMYK 输入 · CLI · 自动选格式的"魔法" · 图库/评级/管理类功能 · GPX 轨迹自动匹配

## 5. 决策背后的硬事实

1. **OIIO 编码无性能优势**——它内部就是调用这些库；直连的意义在参数覆盖（jpeg-li 根本不在 OIIO 编码矩阵里；OIIO 的 HEIF/AVIF 输出基本只暴露一个 quality）。
2. **GPL 早已注定**：Exiv2 是 GPLv2+，只要用它应用就必须整体开源——x265 的加入没有增加任何许可代价。
3. **坐标系坑**：高德（及 Google 中国区）底图是 GCJ-02，与 GPS 标准 WGS-84 存在百米级非线性偏移；地图选点写入 EXIF 前必须自动逆变换。
4. **"macOS 几百行"的参照系**不适用于 Win/Linux：现实预期约 5–8k 行 C++（管线 ~1k + GUI 2–4k + 参数表/胶水 ~2k），在桌面软件尺度上仍是小而美（对比：OIIO 自身十几万行）。

## 6. 设计阶段需核实的技术风险（按风险排序）

| # | 风险 | 影响 | 预案 |
|---|---|---|---|
| R1 | HEIF/AVIF/JXL 容器内 EXIF/XMP 写入 | **已定性**：查证确认 Exiv2 对这三种格式只读 → 混合写入路径定稿（`design.md` §5.2）；剩余验证点：PNG 的 eXIf chunk 写入 |
| R2 | vcpkg 全功能构建 | **具体化**：查证 vcpkg libjxl port 不含 jpeg-li（且 jpegli 已独立仓库）→ 自建 overlay port；待查：libheif svt-av1 feature、OIIO 插件 features、Exiv2 bmff 开关 | overlay port；最坏自编依赖链 |
| R3 | jpeg-li 12 位 JPEG | **已关闭**：查证确认仅 8 位输出（但接受 float32/16 位输入，内部浮点）→ 16 位源转 JPEG 走降档警示 |
| R4 | SVT-AV1 经 libheif 的参数透传完整度 | AVIF 参数暴露面 | 必要时底层 API 直调 SVT-AV1 |
| R5 | lcms2 浮点变换比 8bit LUT 慢 | 吞吐下降 | 用户已明确质量优先，默认浮点不变 |
| R6 | 高德瓦片直连属 ToS 灰色地带（远比 Google 宽松，开源实践普遍） | 极端情况下底图不可用 | OSM 为内置兜底 |
| R7 | GCJ-02→WGS-84 逆变换精度（公开迭代算法约 1–2m） | GPS 精度 | 足够——照片 GPS 本身就是米级精度 |

## 7. 许可证全景（结论：整体 GPLv3）

- 传染源：Exiv2（GPLv2+）、x265（GPLv2+）
- 兼容：libheif（LGPLv3）、Qt（LGPLv3 动态链接）
- 宽松：libjxl（BSD；jpegli 已独立为 google/jpegli 仓库）、OIIO（**Apache-2.0**，2023 年自 BSD 重授权，已查证）、SVT-AV1 / libaom（BSD + 专利授权）、libwebp（BSD）、lcms2（MIT）、libpng/libtiff（permissive）、spdlog（MIT）
- ⚠️ HEVC 专利池对**公开发行**始终存在理论风险（这是所有带 HEVC 编码的免费软件的共同处境）；自用/内部使用无碍。AVIF / JPEG XL 免版税。

## 8. 建议开发顺序（供设计阶段展开；**已被 §9 第 8 条的 M0–M3 重排取代**，保留作历史记录）

1. **M1 管线核心**：OIIO 解码 + lcms2 色彩 + 全部 8 编码器 + 文件级并行 + 文本日志（无 UI 的骨架先跑通）
2. **M2 最小 GUI**：三步流程 + 数据驱动参数区 + 进度 + 预设
3. **M3 元数据全套**：EXIF/XMP 编辑器、批量规则 + 单文件例外、时间偏移、GPS 手动写入
4. **M4 地图选点 + Mica + 打磨分发**（zip / AppImage）

## 9. 设计阶段修订（5 轮设计问答后）

设计定稿见 `design.md`，参数清单草案见 `param-catalog.md`。对本文档的增量修订：

1. **新增『仅元数据』输出模式**：同格式零重编码、只替换容器内元数据（JPEG/PNG/TIFF/WebP 走 Exiv2 无损重写；JXL 走 box 替换；HEIF/AVIF v1 不支持）。
2. **参数系统四层模型**：格式 → 后端（SVT-AV1/libaom）→ 编码技术（VarDCT/Modular、有损/无损、TIFF 压缩方案）→ 参数（核心+高级折叠），可见性/锁定谓词驱动；HEIF/AVIF 参数由 libheif 运行时内省。
3. **管线边界策略定稿**：灰度全程保留、alpha 合成底色+警示、多页/动图取首页、默认视觉透明档、float→整型标准舍入无抖动。
4. **砍到 v2**：JPEG→JXL 码流级无损转封装（v1 管线保持单一）。
5. **工程定稿**：先 Linux 后 Windows；Qt 官方安装器+系统包，图像库 vcpkg+jpegli overlay；双平台 CI+自动发布；单元+金样回放；便携优先落盘；英文日志存数据目录 logs/；dev-only 测试入口（`--dev`，发布构建不含）。
6. 查证事实更新：见 §5、§6、§7 中"已查证"标注（OIIO Apache-2.0、jpegli 独立仓库、Exiv2 写支持矩阵、jpegli 仅 8 位输出）。
7. **设计复审修订（design.md v1.1）**：① jpegli 统一为全程序唯一 libjpeg（消除双 libjpeg 同名符号冲突，OIIO 解码同步升级）；② 色彩变换统一"源→RGB(A)"单一路径，灰度仅"保持原样"时原生保留；③ 缩略图 v1 假定 sRGB（显示器 ICC 留 v1.1）；④ Windows CI 延后至切换 Windows 开发时；⑤ 文件页并入左侧常驻区，步骤导航 4→3；⑥ 金样回放分级（冒烟级 / 断言级，阶段归属以第 8 条 M0–M3 重排为准：冒烟=M1、断言=M2）；⑦ 编码器内部线程全关，仅文件级并行；⑧ 补齐 15 项细节缺口（EXIF 载荷生成路径、像素预算 2× 峰值、通道集 {1,2,3,4}、同名冲突策略、运行期锁定、设置对话框、GPS 有理数编码、MakerNote 拷贝、XMP 仅 x-default、JXL 色彩暴露 R13、AppImage 捆绑 Qt、zstd feature、源树守卫、日志 flush、队列顺序）。
8. **里程碑重排（design.md v1.2，M0–M3 大爆炸式开发）**：M0 = 环境/依赖/编译准备（六 Spike 前置引爆全部外部风险 + Link Probe CI 哨兵 + 语料库 + 参数表冻结 + 断言 schema 冻结）；M1 = 一次性全部编码（底向上，**鼓点纪律**：每落一模块 `--dev` 全语料跑一遍；单测随码走；接口首日冻结）；M2 = Linux debug 收口（ASan/UBSan/TSan + 回归基线 diff + offscreen UI 冒烟 + AppImage 烟测）；M3 = Windows bring-up + 双平台发布（MSVC 风险独立隔离）。Qt 统一 aqt 拉取官方 6.8 LTS（两平台/CI 同源）；vcpkg baseline 钉死 + binary cache。
