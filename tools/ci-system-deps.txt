# PhotoPipeline — CI/构建机 系统依赖清单（M2-T19）
# SPDX-License-Identifier: GPL-3.0-or-later
#
# 单一事实来源：`build-test.yml` 的三个 job 与 `warm-cache.yml` 播种 workflow 全部消费本文件，
# 不再各自内联 `apt-get install` 列表 —— "每轮 CI 只暴露一个缺包" 的结构性根因就是列表分散。
#
# 消费方式（三种等价，推荐第一种）：
#   bash tools/ci-install-deps.sh
#   sudo apt-get install -y $(sed -e 's/#.*//' tools/ci-system-deps.txt | tr '\n' ' ')
#   ⚠ 不要写 `grep -v '^#' tools/ci-system-deps.txt | tr '\n' ' '`：本文件是**行尾注释**格式，
#     那样会把 `#` 与注释文字当成包名喂给 apt（`E: Unable to locate package #`），必须先剥注释。
#
# 覆盖自检（本地/CI 皆可跑，未覆盖项必须为 0）：
#   bash tools/ci-check-deps.sh build/release-dev
#
# 清单怎么来的（M2-T19 ① 的系统化推导，不是逐个试错）：
#   1. 对**随包 ELF 全集的传递闭包**取 DT_NEEDED soname：
#        ldd 的输入 = 构建树全部可执行/共享库 + vcpkg_installed/**/*.so*
#                    + Qt 工具链中**实际随 AppImage 分发**的插件
#                      （platforms/libqoffscreen.so、platforms/libqxcb.so、
#                        imageformats/、iconengines/、styles/、tls/）
#        （刻意**不含** Qt 的 wayland/eglfs/linuxfb/vnc/qml/sql 等插件与库：它们不在分发集里，
#          收进来会引入 libwayland-*/libdrm/libmysqlclient/libpq 等无关包。）
#   2. `ldconfig -p` 把 soname 解析到 /usr/lib/x86_64-linux-gnu/<soname>，`dpkg -S` 反查所属包。
#   3. 去掉基础包（libc6 / libstdc++6 / libgcc-s1 —— 见文件末"隐式覆盖"说明）。
#   4. 再加上链接期需要的 -dev 包（提供 .so 符号链接与头文件）与构建工具。
#   本清单在 Ubuntu 24.04（CI runner）与 26.04（本机）上都成立；发行版改名由
#   tools/ci-install-deps.sh 的"本发行版不存在的包"容错 + tools/ci-check-deps.sh 的
#   soname 级硬断言共同兜住（改名可以容忍，缺 soname 一定会红）。
#
# 历史教训（每一项都曾让 CI 红一整轮，故列入清单并注明根因）：
#   nasm          → svt-av1 / aom / libwebp 的 x86 SIMD 端口 BUILD_FAILED（run 35513359184）
#   libgl-dev     → CMake FindOpenGL 缺 OPENGL_INCLUDE_DIR（run 35517286929）
#   libglx-dev    → 缺 OPENGL_glx_LIBRARY（同上）
#   libopengl-dev → 缺 OPENGL_opengl_LIBRARY（同上）
#   libegl1       → libQt6Gui.so.6 的 NEEDED libEGL.so.1 不在 ld 搜索路径 ⇒
#                   `undefined reference to eglGetCurrentContext` 等 19 个符号（run 35519174344）
